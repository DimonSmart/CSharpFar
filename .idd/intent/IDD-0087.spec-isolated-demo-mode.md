# IDD-0087 - Isolated Demo Mode specification

Related:
- IDD-0001 (product-wide intent)
- IDD-0010 (filesystem operations)
- IDD-0030 (panel-load errors and unregistered-source transitions)
- IDD-0061 (native plugins and source registration)
- IDD-0088 (documentation demo recording)

## Goal and ownership

Provide a safe, reproducible session where the file manager operates on a
snapshot of a user-selected directory instead of the user's live filesystem.
This document exclusively owns Demo Mode startup, in-memory source behavior,
source-registry isolation and session configuration safety.

`IDD-0088` owns recording scenarios and media artifacts that use this
environment. General panel error and rejected-source transition behavior
is owned by `IDD-0030`, including restoration of previous panel state.

## Startup and snapshot

- `csharpfar --demo <root-path>` is supported by Windows, Linux and macOS
  hosts. The parameter identifies a readable directory to import.
- Missing `--demo` path, nonexistent directory or unreadable input fails
  before normal UI startup with a clear CLI error and nonzero exit status.
- Demo mode is selected before creating, reading or validating the normal
  user's persistent application settings or credentials.
- Import the physical fixture once at startup into an in-memory filesystem
  with one platform-independent logical root, `/`. After successful import,
  the physical fixture is not used as live state for runtime operations.
- Both panels initially navigate the logical demo source. The physical
  fixture path must not be exposed as the panel location or as runtime file
  operation state. Normal startup without `--demo` remains unchanged.

## Runtime isolation

- The session's reachable panel-source registry is an allow-list containing
  only the demo filesystem source. No real local volume or other provider
  can become a reachable panel or file-operation target through a command,
  forged source-qualified location, or malformed request.
- Reject unregistered/local source targets before physical directory
  enumeration, file existence checks, other local reads or mutations.
  A `SourceId.Local` identifier alone never authorizes local I/O:
  a local-only command must also verify the current panel is local and
  that its source is registered in the active runtime composition.
- A rejected navigation transition leaves the previous source-qualified
  location and panel state intact, without a panel retry error for the
  rejected target, as specified by `IDD-0030`.
- Viewer, editor, copy, move, rename, create and delete operate on the
  imported in-memory source through the normal supported capabilities.
  Changes remain visible to the current demo session, but disappear when
  it ends; the original physical fixture remains unchanged.
- External shell command execution, external file/application launching
  and built-in network providers/modules are unavailable in the demo
  composition. Drive/volume selection cannot expose physical volumes.
- Demo-only services and registrations enforce isolation at composition
  boundaries; security must not rely on scattered UI-level mode checks.
- The demo session uses an isolated ephemeral configuration directory.
  Its settings and history changes do not read, create, modify or replace
  the normal user's `settings.json`, histories or credential-store data.

## Non-goals

- Running commands or inspecting real local or remote resources from the
  demo session.
- Persisting demo mutations or restoring a demo session on the next launch.
- Defining recording scripts, screenshots or media conversion (`IDD-0088`).
- Redefining ordinary panel retry and source-error UI (`IDD-0030`).

## Acceptance criteria

1. Valid `--demo` input opens two panels on the isolated logical source;
   invalid input fails early and nonzero without normal UI startup.
2. After import, normal panel/viewer/editor and supported file operations
   use the snapshot, not the physical fixture, and no panel exposes the
   physical fixture path as its current location.
3. Unregistered or forged local sources fail before any local filesystem
   access or mutation and cannot escape the in-memory composition.
4. Rejected panel navigation preserves existing state according to
   `IDD-0030`; it does not replace the current panel with an error for
   the rejected source.
5. Shell, external launching, real-volume navigation and built-in network
   providers are inaccessible in Demo Mode.
6. Normal settings, history, credentials and the imported physical fixture
   remain unchanged after a demo session, even if the user edits demo data.

## Verification

Exercise a readable fixture and each invalid `--demo` input before UI startup.
Within a single session, view, edit, create, copy, move, rename and delete
items, checking both visible in-memory results and unchanged fixture bytes.
Attempt unregistered local locations, forged operation operands, volume
switching, external shell/file launching and built-in network access;
assert rejection happens before any real filesystem I/O. Verify preservation
of source-qualified location, cursor, selection, capabilities and transient
navigation state under the `IDD-0030` transition contract. Compare the
normal configuration and credential store before and after a demo run.
