# IDD-0009 - Open panel item specification

Related:
- IDD-0001
- IDD-0004
- IDD-0007

## Context

Users open directories and files from panel items with `Enter` and mouse
actions. Single-click selection must remain distinct from opening an item.

## Scope / Behavior

- `Enter` on a directory changes the active panel to that directory.
- `Enter` on `..` navigates to the parent directory using the parent-navigation
  behavior from `IDD-0004`.
- Before default file launching or viewing, Enter invokes optional registered file-open
  handlers (IDD-0061). If exactly one handler claims a file, its result controls
  the action: not handled falls through to default behavior; opened switches to
  a nested panel source; cancelled stops; failure reports an error without
  launching the file through the OS.
- Two handlers claiming the same item are an error (never silently ordered
  by file extension); handler exceptions are reported as failures.
- A file-open handler runs asynchronously, with completion dispatched onto
  the terminal UI thread. No partial pane transition is applied while a handler
  is pending, and an obsolete completion does not replace a pane that navigated
  elsewhere.
- Enter at the root of a nested source returns to the preceding source and
  restores the container item's cursor and panel state. Nested source entries
  use a per-panel LIFO stack; regular parent navigation is unchanged.
- `Enter` on a non-executable local file opens it through its platform file
  association in detached mode. CSharpFar remains usable, keeps its panels
  visible, and does not receive output from the associated application.
- `Enter` on an executable local file launches it according to the
  current-console execution rules.
- A single mouse click on an item makes it current without opening it.
- A double-click on a directory behaves like `Enter` on that directory.
- A double-click on a regular file behaves like `Enter` on that file.
- Two separate single clicks on different items must not be interpreted as a
  double-click open.
- Open failures are reported to the user and leave the panel in a predictable
  state.

## Non-goals

- This spec does not define custom file associations.
- This spec does not require opening unsafe executables without normal platform
  checks.

## Acceptance criteria

- `Enter` and double-click use the same routing for directories and files.
- Opening a non-executable local file leaves the panels visible and returns to
  CSharpFar without waiting for the associated application.
- Single-click changes only the current item.
- Double-click detection is item-specific and time-bounded.
- Failed opens report an error without corrupting panel state.
- Parent item opening follows the cursor restoration behavior from `IDD-0004`.
- A nested source can be opened and exited without archive-specific path parsing.
