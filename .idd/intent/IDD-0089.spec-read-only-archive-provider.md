# IDD-0089 - Read-only archive provider

Related: IDD-0009 (open panel item), IDD-0010 (file operations),
IDD-0032 (file viewer), IDD-0061 (native plugins).

## Intent

CSharpFar lets users browse supported archives as ordinary, read-only
file-panel sources, using existing plugin, navigation, viewer and copy routes.

## Observable behavior

- Enter or double-click on ZIP, RAR/RAR5, 7z, TAR, TAR.GZ or TGZ
  opens a nested panel after examining actual content; unsupported or corrupt
  data produces an error and does not launch an external application.
- File names and directory metadata are indexed on open. Missing ancestor
  directories are synthesized. Internal names preserve case and Unicode.
  Identical normalized names are rejected rather than arbitrarily resolved.
- Inside the archive, ordinary panel navigation, selection, sorting,
  quick search, F3 viewing and F5 copying are available. Copying whole
  directories preserves the hierarchy and empty folders. Read-only
  capabilities prevent editing, deletion, renaming and moves out of the archive.
- Going above an archive's root restores the container's source and cursor.
  Nested archives can be opened to a bounded depth. Independent opens have
  independent source identity and dispose after the last panel or operation use.
- Decompression is on demand, streamed and bounded; it never populates an
  in-memory cache of all uncompressed file data.
- Path traversal, absolute paths, ambiguous entries, links, encrypted entries
  and unsupported multipart archives fail safely with explanatory diagnostics.
  A changed or removed local archive is not silently read using an old index.
- Limits for entry count, expanded size, temporary disk, compression ratio
  and nesting depth are documented in docs/archive-provider.md.

## Ownership and boundaries

IDD-0061 owns generic file-open registration, lifecycle and source identity.
IDD-0009 owns navigation and cursor restoration; IDD-0010 owns conflicts,
progress, cancel and cross-provider copy; IDD-0032 owns rendering and viewer.
This spec owns only the archive-specific behavior and security constraints.

## Non-goals

Writing to archives, password input, splitting/joining volumes, repair,
external archiver executables and a separate extraction UI.

## Verification

Test representative ZIP, TAR and GZip-compressed TAR fixtures, indexed
directories and Unicode paths, normal provider copying, nested archives,
non-seekable source streams, stale archives and malformed or dangerous
entries. Include RAR/RAR5 and 7z solid/non-solid compatibility fixtures
in platform CI once permitted redistributable fixtures are available.
