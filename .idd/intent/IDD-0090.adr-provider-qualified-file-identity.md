# IDD-0090 - Provider-qualified file identity

Type: ADR
Status: Accepted

Related: IDD-0007, IDD-0010, IDD-0012, IDD-0061, IDD-0074, IDD-0075

## Context

String paths and qualified locations were separately mutable in selection and operation requests. Their disagreement could target the wrong provider or collapse distinct names. Path composition and equality also assumed local or slash-delimited paths.

## Decision

Use PanelLocation (source ID and provider path) for logical identity. IFilePanelSource owns normalization, comparison, path composition, file name extraction and relative segments; a collection snapshots provider semantics via PanelLocationComparer. Unknown provider comparison defaults to ordinal; local behavior follows its documented OS policy. Do not merge source IDs. Physical identity for alias and self-copy protection remains separate. Local-only execution can project verified local locations to strings. Destination templates are expressions until evaluated.

## Alternatives considered

Keep both sets or both request fields: rejected because divergence remains possible. Preserve the old mutable HashSet<string> SDK property as a facade: rejected because nonvirtual mutations cannot reliably proxy provider-qualified identity. Change only string comparison: rejected because identical paths in different providers are different objects.

## Consequences

SDK 2 is a deliberate incompatible release. The manifest API and both assembly/package versions advance; v1 plugins must be rebuilt and migrated before loading. The previous v1 API baseline is preserved by commit reference; a new pinned v2 baseline is checked in CI. Provider semantics must remain stable for a source's lifetime. No new provider or filesystem transaction architecture is introduced.
