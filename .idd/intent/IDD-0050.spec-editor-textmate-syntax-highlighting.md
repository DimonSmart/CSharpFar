# IDD-0050 - Editor TextMate syntax highlighting specification

Related:
- IDD-0046 (editor core and rendering)
- IDD-0049 (Far-like editing commands)
- IDD-0013 (shared function-key presentation)
- IDD-0038 (single-line input controls)
- IDD-0067 (stable-frame and modal composition)

## Goal and authority

The built-in F4 editor provides **lexical TextMate syntax coloring**
without modifying text, selection, cursor, bookmarks, search, undo/redo,
dirty state, save behavior or other editor commands. IDD-0046 governs
core editing; this specification governs highlighting, language/theme
selection and safety fallbacks.

This is the normative behavioral and durable integration contract.
Historical library comparisons, suggested private classes, cache
implementations, phased workplans and detailed test recipes are retained
in the [non-normative engineering reference](../../docs/architecture/editor-syntax-highlighting-implementation-reference.md).
That older plan does not constrain current internal class structure.

## Languages, themes and rendering

- Highlighting uses TextMate lexical scopes, not AST/LSP semantics.
  Supported bundled grammars include at least **C#, JSON, XML,
  Markdown, PowerShell and YAML**.
- Automatic detection recognizes filename extensions and known exact
  filenames such as `Dockerfile`. An explicit session language or
  validated TextMate scope overrides automatic detection.
- Unknown file types and missing/invalid grammars fall back to plain
  text without error dialogs that prevent editing.
- Syntax color spans refer to logical text indexes, mapped through
  the editor's tab expansion, Unicode and terminal-cell rendering.
  Plain style is the base; syntax style is overlaid by selection
  and finally cursor visibility. Syntax coloring never changes
  document geometry.
- TextMate scopes and theme colors map to available terminal colors;
  supported true color may be used, with safe console-palette fallback.
  Unknown or unmappable colors use the editor's readable default style.
  Invalid themes fall back to a suitable built-in theme.
- TextMate-specific library classes must not leak into the editor core
  or generic console renderer. Highlighting belongs behind the
  editor-domain boundary, not a public plugin API.

## Tokenization, cache and failure behavior

- Tokenization carries grammar state across adjacent lines so
  multiline comments and strings remain correctly highlighted.
- Edits invalidate affected lines and dependent following grammar
  state. Cursor-only moves do not invalidate syntax; a language or
  theme change updates appropriate syntax/color presentation.
- Tokenization is bounded and largely focused on visible text.
  Changing only the caret, status or function-key modifier must
  not retokenize unchanged content or bypass IDD-0067 accepted
  frame semantics.
- Lines longer than `Editor.SyntaxMaxLineLength` display as plain
  text. Timeout, tokenization failure or invalid custom assets
  cannot freeze the editor or block save, close, search, copy,
  paste, undo or redo. Failures are reported through diagnostics.
- Syntax rendering is read-only. It does not mutate buffers,
  undo history, selection, bookmarks or document revisions.

## Settings and user controls

These existing persisted editor settings retain their meanings:

| Setting | Default | Meaning |
| --- | --- | --- |
| `Editor.SyntaxHighlightingEnabled` | `true` | Default highlighting; false means plain text |
| `Editor.SyntaxTheme` | `"Dark+"` | Requested theme with fallback |
| `Editor.SyntaxLanguage` | `"auto"` | Automatic or explicit language |
| `Editor.SyntaxMaxLineLength` | `20000` | Long-line plain-text fallback |
| `Editor.SyntaxTokenizationTimeoutMs` | `50` | Tokenization time budget |
| `Editor.SyntaxMaxSynchronousLines` | `300` | Bound synchronous work |
| `Editor.SyntaxUseTrueColor` | `"auto"` | Color capability preference/fallback |
| `Editor.SyntaxFallbackToPlainText` | `true` | Graceful no-grammar/no-tokenization fallback |
| `Editor.SyntaxUserGrammarsPath` | unset | Optional user grammar directory |
| `Editor.SyntaxUserThemesPath` | unset | Optional user theme directory |

- `Alt+H` toggles syntax coloring for the active editor session.
  `Alt+L` opens the searchable `Syntax language` selector;
  `Alt+T` opens the `Syntax theme` selector.
- The language selector presents `Auto` first, known grammar
  languages sorted by display name, and `Custom TextMate scope...`
  last. Search matches display name, canonical language ID,
  aliases and TextMate scope case-insensitively.
- Selecting known language stores its canonical ID; selecting
  `Auto` stores `auto`. Existing `auto` highlights Auto in the
  dialog rather than the detected language. Known saved IDs,
  aliases and scopes select their matching item.
- A saved unknown `source.*` or `text.*` scope selects Custom.
  Other unknown saved values display Auto as a safe default
  without silently changing the stored session value.
- Custom scopes accept trimmed, nonempty values beginning with
  `source.` or `text.`. Invalid input gets in-dialog validation;
  cancelling custom scope entry returns to the language list,
  and cancelling that list changes nothing.
- The theme picker offers a stable sorted set of available
  themes and highlights the effective fallback when an unknown
  value is stored. Confirming a choice saves its canonical name.
  Merely opening, navigating, filtering or cancelling the
  language/theme dialogs never changes settings or syntax cache.
- Missing user grammar/theme directories are ignored; invalid
  files do not break bundled grammars and are surfaced through
  diagnostics. Their paths do not require a new plugin system.

## Diagnostics and non-goals

- Diagnostics report effective grammar/language, theme, color
  mapping or fallback, disabled status and relevant grammar,
  theme or tokenization failures.
- FarColorer/HRC, native Colorer, LSP/semantic highlighting,
  completion, formatting, IDE diagnostics, outline, viewer
  highlighting, third-party highlighter plugins and full
  VS Code font-style fidelity are not required.
- No requirement to retain private types, implementation stages,
  detailed cache object graphs or historical test class names.

## Acceptance criteria

1. Minimum supported languages are highlighted; unknown/invalid
   grammars show plain text and leave the editor usable.
2. Selection/caret precedence, tabs, Unicode cell widths and
   resize remain correct with syntax styles enabled.
3. Editing, bookmarks, clipboard, undo/redo, find, replace and
   save behave independently from the syntax subsystem.
4. Theme/language controls preserve auto, alias, scope,
   fallback, search and cancellation semantics.
5. Multiline grammar states update after dependent edits while
   cursor-only/status-only updates reuse unchanged syntax.
6. Long lines, tokenization failures and invalid custom files
   degrade safely with diagnostics without blocking editor use.
7. Existing settings and command chords retain their behavior.

## Verification

Cover all six minimum grammar languages, filename recognition,
unknown-file fallback, multiline grammar changes, visual style
priority, cache invalidation boundaries, long-line timeout/error
fallback, theme and language selection including unknown stored
values and custom scopes, and preservation of editing behavior.
Check responsiveness and viewport correctness on large files,
in narrow terminals and through modal dialogs.
