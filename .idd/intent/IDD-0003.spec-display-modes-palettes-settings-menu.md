# IDD-0003 - Display modes, palettes, and settings menu specification

Related:
- IDD-0007 (Panels settings contents and apply/persist effects)
- IDD-0013 (function-key bar labels and availability)
- IDD-0028 (workspace state and swapping panel view modes)
- IDD-0050 (editor syntax highlighting settings)
- IDD-0062 / IDD-0067 (shared controls and modal composition)

## Context

CSharpFar needs configurable panel display modes, configurable console palettes,
and an in-application settings dialog so users can change the main visual
presentation without editing configuration files manually.

The settings surface also serves as the first consumer of a reusable,
application-independent settings dialog in `CSharpFar.Ui`. The reusable layer
owns presentation and interaction only; CSharpFar continues to own its settings
model, persistence, and runtime effects.

## Scope / Behavior

Panel display modes:

- `Full` shows the detailed file list with name, size, and directory marker.
- `BriefTwoColumns` shows two Far-like name columns without file sizes or
  `<DIR>` markers in the list.
- `BriefTwoColumns` fills the first column top-to-bottom, then the second
  column.
- Cursor highlighting applies only to the current item cell in the relevant
  column.
- Up/down navigation moves through the logical item list, not only through the
  visual column.
- Long names are clipped to the column width.
- The user can switch modes through documented hotkeys and through settings.
- The two physical panels retain independent persisted view modes. The `Panels`
  settings controls for these values are owned by `IDD-0007`; workspace and
  panel-swap behavior are owned by `IDD-0028`.

Palettes:

- A `Default` palette preserves the existing CSharpFar look.
- A `FarClassic` palette approximates Far Manager colors.
- Renderers obtain colors from the active palette instead of hard-coded color
  literals.
- Selected file rows use panel-specific selection colors in both modes:
  Yellow on DarkCyan in Default and Black on Green in FarClassic. The shared
  UI selection palette remains unchanged. Cursor highlight takes priority
  over selection and user file highlight rules retain their precedence.
- The active palette name is persisted in settings.
- An unknown palette name in settings falls back to `Default` without crashing.
- `FarClassic` panel titles use text color rather than a wide title background.
- `FarClassic` uses a green cursor background with black foreground.

Settings menu:

- `CSharpFar.Ui` provides a reusable high-level settings dialog composed from
  the standard modal, routed list, form, focus, pointer, and scrollbar
  infrastructure.
- A generic settings dialog contains deterministic, uniquely identified pages;
  each page is described by a title and ordinary `FormRow` controls.
- Generic settings UI has no dependency on `AppSettings`, persistence stores,
  panel/editor/shell concepts, or other CSharpFar application models.
- Page controls are materialized once for one dialog lifetime. Switching pages,
  resizing, and split/compact transitions do not recreate controls or lose
  edited values.
- Normal layout shows page navigation beside the selected page. Narrow layouts
  switch to a compact navigation/page presentation with an explicit way back to
  page navigation.
- Navigation and every settings page retain independent scroll state. The
  selected navigation item stays visible.
- Keyboard and mouse input use the standard routed UI lifecycle. `Tab` traverses
  navigation, page controls, and footer actions; `Right`/`Enter` enters the
  selected page; an unhandled `Left` from page content returns to navigation.
- `Esc` closes without saving changes. `F10` and the Save action save and close.
- Save validation runs all pages in deterministic page order, including pages
  that have not yet been opened. An invalid hidden page is selected, scrolled
  to the invalid control, focused, and its error is shown.
- The generic dialog returns only Saved/Cancelled lifecycle state. CSharpFar
  owns the editable values and applies/persists them only after Saved.
- `InitialPageId` selects a known page; a missing or unknown ID falls back to
  the first page.
- CSharpFar uses the generic settings dialog for panel options, palette, and
  other application settings, including editor syntax options owned by
  `IDD-0050`. `IDD-0007` exclusively defines the `Panels` page, its groups,
  staged panel values, and apply/refresh/persist effects.
- `Options` exposes a single `Settings...` entry rather than duplicate
  immediate checkboxes for ordinary panel settings.
- Palette preview may theme the settings dialog while open, but cancelling
  leaves the global palette unchanged. The generic Save/Cancel lifecycle is
  specified here; panel-specific side effects are not.

Main-screen Far-like polish:

- `BriefTwoColumns` displays a column header equivalent to `n Name | Name`,
  where `n` indicates name sorting.
- Panel status/summary options and their values are owned by `IDD-0007`.
- Dynamic function-key bar actions, labels and availability are owned by
  `IDD-0013`; this display specification does not define a static key map.
- The current time is drawn in the top-right area as `H:mm` without breaking
  the panel border or exceeding screen width.

## Non-goals

- This spec does not require removing existing display modes.
- This spec does not require every future setting to be exposed immediately.
- The generic settings component does not clone application settings, persist
  them, or apply application-specific runtime side effects.
- The settings component does not introduce a second modal, focus, pointer, or
  scrolling framework.

## Acceptance criteria

- `Full` and `BriefTwoColumns` are separate modes.
- The user can switch display mode and palette.
- Selected display mode and palette are restored after restart.
- Renderers use the active palette.
- The reusable settings dialog is application-independent and built on the
  existing routed UI components.
- Settings pages preserve control identity, draft values, page scroll positions,
  and logical focus across page switches and resize/layout transitions.
- Save/Cancel, `F10`/`Esc`, keyboard traversal, mouse interaction, hidden-page
  validation, compact layout, and initial-page selection work through the
  standard modal lifecycle.
- CSharpFar persists settings only after a successful Save and preserves all
  settings previously available in its settings dialog.
- The `Panels` settings page and panel-specific save effects satisfy
  `IDD-0007` without duplicating that page's acceptance criteria here.
- The main-screen clock renders without overlapping other UI; panel status
  and function-key details follow `IDD-0007` and `IDD-0013`.
