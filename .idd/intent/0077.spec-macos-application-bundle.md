# 0077 - macOS application bundle

## Intent

CSharpFar provides a normal macOS `CSharpFar.app` application bundle for users
who expect to install and launch the program from Applications, Finder,
Spotlight, or Launchpad, without converting the terminal UI into a native GUI.

The application bundle is an additional distribution shape over the existing
self-contained macOS executable. The portable CLI archives remain supported.

## Related specifications

- 0036 - Application icon
- 0064 - Unix terminal input

## Behavior

A release publishes architecture-specific application archives for both
supported macOS architectures:

- `CSharpFar-v<version>-osx-arm64-app.zip` for Apple Silicon;
- `CSharpFar-v<version>-osx-x64-app.zip` for Intel.

Each archive contains `CSharpFar.app` with a conventional macOS bundle layout:

- `Contents/Info.plist` contains the bundle identity and release version;
- `Contents/MacOS/CSharpFar` is the bundle launcher;
- `Contents/Resources/csharpfar` is the same self-contained terminal executable
  produced for the corresponding CLI release;
- `Contents/Resources/CSharpFar.icns` is the application icon;
- `Contents/Resources/launch.command` is the Terminal entry point used for
  Finder-style launches.

The bundle identifier is `com.dimonsmart.csharpfar`.

CSharpFar remains a terminal application. When the bundle launcher already has
a terminal or receives explicit command-line arguments, it executes the bundled
`csharpfar` binary directly. When launched without a terminal, as from Finder,
it opens the bundled terminal entry point with Terminal.app and exits.

A Finder launch starts CSharpFar in the user's home directory. The application
does not introduce a separate GUI shell merely to obtain a Finder icon.

The macOS icon is derived from the existing original CSharpFar icon asset so
Windows and macOS retain the same product identity. Packaging may convert the
repository icon into the `.icns` sizes required by macOS.

The application bundle is assembled on macOS because the packaging step uses
macOS bundle/icon tooling. This does not require the managed application itself
to be compiled on macOS: future release-pipeline optimization may cross-publish
the `osx-*` executable on another OS and reserve macOS runners for bundle
assembly, terminal verification, signing, or notarization.

## Release integration

The Release workflow creates the app archive from the already published
architecture-specific macOS executable and publishes it alongside the existing
CLI archive.

Each app archive has a SHA-256 entry in `SHA256SUMS.txt` and receives the same
GitHub artifact attestation treatment as the portable release archive.

Release notes distinguish the Finder/Applications app archives from the
portable CLI archives.

## Signing and notarization

Application bundles are currently unsigned and not notarized. Users may need to
use Finder's **Open** action on first launch.

Code signing and Apple notarization are distribution-hardening work and may be
added later without changing the bundle/launcher contract in this specification.

## Non-goals

- Do not replace the terminal UI with AppKit, SwiftUI, Catalyst, or another GUI.
- Do not remove or weaken the portable `osx-arm64` and `osx-x64` CLI releases.
- Do not require a separately installed .NET runtime.
- Do not duplicate the CSharpFar application implementation inside a macOS-only
  UI project.
- Do not make signing credentials a prerequisite for producing development or
  experimental app bundles.

## Acceptance criteria

- Releases contain `CSharpFar.app` ZIP archives for Apple Silicon and Intel.
- The bundle contains a valid `Info.plist`, application icon, executable
  launcher, terminal launcher, and self-contained `csharpfar` binary.
- `CFBundleShortVersionString` and `CFBundleVersion` match the release version.
- The bundle launcher can execute `--version` directly for automated checks.
- Launching the app from Finder opens CSharpFar in Terminal rather than trying
  to run the terminal UI without a terminal.
- App archives are included in release checksums and attestations.
- Existing portable macOS CLI assets continue to be published.

## Verification

Automated release verification:

1. Validate `Info.plist` with `plutil`.
2. Verify the bundle launcher executes the bundled binary and reports the
   expected release version.
3. Verify both app ZIP assets are generated and checksummed.

Manual macOS verification:

1. Unpack the architecture-matching ZIP.
2. Move `CSharpFar.app` to Applications.
3. Open it from Finder and confirm Terminal opens with CSharpFar running.
4. Confirm the application icon is visible in Finder/Applications.
5. Confirm the portable `csharpfar` CLI archive still runs independently.
