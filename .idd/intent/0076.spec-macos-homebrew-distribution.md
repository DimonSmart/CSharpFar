# 0076 - macOS Homebrew distribution

## Intent

CSharpFar provides Homebrew as the primary installation and upgrade path on
macOS while continuing to publish transparent self-contained Apple Silicon and
Intel archives through GitHub Releases.

The Homebrew metadata is derived from release artifacts automatically so a
normal CSharpFar release does not require a separate manual package-maintenance
step.

## Behavior

The main `DimonSmart/CSharpFar` repository also acts as a custom Homebrew tap.
Because its GitHub repository name does not use Homebrew's `homebrew-<tap>`
convention, users add it with the explicit repository URL:

```bash
brew tap dimonsmart/csharpfar https://github.com/DimonSmart/CSharpFar.git
brew install dimonsmart/csharpfar/csharpfar
```

Homebrew is the recommended macOS installation method in README and installation
documentation.

The Homebrew formula installs the existing self-contained `csharpfar` release
binary and does not require a separately installed .NET runtime.

The formula supports both currently published macOS architectures:

- Apple Silicon uses `CSharpFar-v<version>-osx-arm64.tar.gz`;
- Intel uses `CSharpFar-v<version>-osx-x64.tar.gz`.

The formula selects the archive from the current CPU architecture and installs
`csharpfar` into Homebrew's binary path.

The formula has a Homebrew test that executes `csharpfar --version` and verifies
that the installed executable reports the formula version.

Users upgrade through normal Homebrew commands:

```bash
brew update
brew upgrade dimonsmart/csharpfar/csharpfar
```

## Formula publication

`Formula/csharpfar.rb` is generated from a published GitHub Release rather than
edited manually.

`eng/packaging/update-homebrew-formula.ps1` accepts the release version and the
release `SHA256SUMS.txt`. It requires checksums for both macOS archives and
writes a formula containing immutable versioned release URLs and matching
SHA-256 hashes.

The `Homebrew` GitHub Actions workflow refreshes the formula after a successful
`Release` workflow. It resolves the release tag from the completed release run,
downloads `SHA256SUMS.txt`, generates and syntax-checks the formula, and commits
updated Homebrew metadata to `master`.

`eng/packaging/homebrew-current-tag.txt` records the release currently targeted
by the formula. A change to this file also triggers the Homebrew workflow, which
provides a deterministic bootstrap/recovery mechanism for an already-published
release. The workflow can additionally be run manually with an explicit tag.

Formula-generation commits are distribution metadata updates. They do not
create another release because the Release workflow is tag-triggered.

## Architecture and patterns

GitHub Releases remain the source of binary history and checksums. Homebrew is a
thin installation layer over those release artifacts rather than a second build
pipeline.

The Homebrew workflow must not rebuild macOS binaries. It consumes only a
successfully completed CSharpFar Release and its checksums. The release workflow
remains responsible for compilation, tests, macOS terminal smoke tests,
packaging, and release publication.

A separate `DimonSmart/homebrew-tap` repository is not required for the current
distribution model. Homebrew supports custom taps with an explicit Git URL, so
keeping Formula and product source in one repository removes cross-repository
credentials and synchronization from the release path.

A dedicated `homebrew-*` repository may be introduced later if the one-command
Homebrew shorthand becomes more valuable than the simpler single-repository
maintenance model. Such a move must preserve the same versioned assets,
architecture selection, SHA-256 verification, and automatic update behavior.

## Non-goals

- Homebrew does not build CSharpFar from source during installation.
- Homebrew does not replace GitHub Releases as the release artifact source.
- Homebrew does not add a .NET runtime dependency for packaged releases.
- The Homebrew workflow does not publish or modify macOS application bundles.
- Code signing and Apple notarization are separate distribution hardening work.

## Acceptance criteria

- README presents Homebrew as the recommended macOS installation method.
- A macOS user can add the CSharpFar tap and install the fully-qualified
  `csharpfar` formula.
- Installation selects `osx-arm64` on Apple Silicon and `osx-x64` on Intel.
- The installed command is available as `csharpfar`.
- Packaged Homebrew installation does not require the .NET runtime.
- `Formula/csharpfar.rb` contains SHA-256 verification for both macOS assets.
- A successful Release workflow is followed by automatic Formula refresh on
  `master`.
- Formula generation fails clearly if either required macOS checksum is absent.
- A previously published release can be used to refresh the Formula through the
  tracked current-tag file or manual Homebrew workflow dispatch.
- Documentation includes install, upgrade, uninstall, version verification, and
  self-test commands.

## Verification

- Validate the generated Formula with Ruby syntax checking.
- Verify both architecture URLs and checksums correspond to the same release
  version.
- On Apple Silicon, install through Homebrew and run `csharpfar --version`.
- On an Intel runner or Intel Mac, install through Homebrew and run
  `csharpfar --version`.
- Run `csharpfar --self-test` separately as a diagnostic check.
