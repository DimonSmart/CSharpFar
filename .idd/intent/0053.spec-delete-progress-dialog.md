# 0053 - Delete progress dialog

Related:
- 0010
- 0019

## Goal

Show file deletion with delete-specific scanning and progress dialogs instead of
reusing the copy progress layout.

## Context

The current file operation progress dialog renders every non-scanning operation as a
copy operation. That makes delete progress show copy wording, a destination line, a
current-file byte progress bar, and resume details that only make sense for copying.

Deletion still needs aggregate progress: deleted item count and deleted byte volume
should remain visible. Before deletion begins, users need visible, cancellable scan
progress rather than an indeterminate preparation state.

## Scope

Implement a delete-specific progress rendering path:

1. Use a delete title for deletion progress.
2. Show deletion status and the current source path.
3. Keep total deleted item count and byte volume visible.
4. Keep elapsed time visible when available.
5. Remove copy-only details from delete progress:
   - destination path;
   - "to" line;
   - current-file byte progress bar;
   - resume offset and rollback details.

Delete preparation is an explicit scanning phase. From the start of a potentially
long scan, it shows the current scanned path and accumulated discovered files,
folders, and data bytes. Because the final denominator is not known until scanning
finishes, scanning shows neither a percentage nor an implied completed total.
Scanning can be cancelled immediately through the standard operation-dialog
lifecycle.

The file-operation service owns scanning and deletion progress. It builds the
delete operation's aggregate size in one traversal before deletion, then uses the
resulting per-source sizes while deleting; it does not recursively recalculate a
source's size immediately before deleting that source. The UI does not inspect the
filesystem or infer operation phases.

## Non-goals

Do not implement in this spec:

1. recycle-bin behavior changes;
2. pause/resume redesign;
3. progress UI changes for copy, move, or create-directory operations except where
   needed to keep the shared dialog code clear.

## Acceptance criteria

- Delete progress dialog title is `Delete`.
- Delete progress does not show copy destination wording.
- Delete progress does not show current-file byte progress or resume details.
- Delete progress still shows deleted file/item count.
- Delete progress still shows deleted byte volume.
- A delete operation reports scanning progress before a long recursive scan and
  transitions to delete progress afterwards.
- Delete scanning shows current path and accumulated files, folders, and bytes
  without a percentage or other artificial denominator.
- Cancelling during delete scanning stops the operation promptly.
- Delete size planning scans each source tree once; deletion reuses its planned
  source size rather than recursively recalculating it.
- Existing copy progress keeps its current copy-specific information.

## Verification

Automated coverage verifies delete-specific progress wording and the reported
deleted byte and item totals. It covers the scanning-to-deleting sequence,
accumulated scanning counters without a percentage, cancellation during scanning,
and reuse of planned source sizes.
