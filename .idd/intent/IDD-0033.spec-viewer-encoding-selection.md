# IDD-0033 - Viewer Encoding Selection specification

Related:
- IDD-0012
- IDD-0014
- IDD-0032
- IDD-0052

## Goal

Let the F3 viewer decode text using automatic encoding detection or a
user-selected encoding while retaining streaming access for both small and
huge files.

Changing encoding must invalidate all decoding-dependent state and redraw
the file near the previous byte position without loading the whole file or
blocking concurrent modification by keeping a viewer-lifetime file handle.

## Context

F3 uses a unified streaming viewer. Automatic text-encoding detection is
shared across the viewer, content search, editor, and Quick View. It recognizes
Unicode BOMs, likely UTF-16, valid UTF-8, and binary-looking input, with a
culture-dependent Windows ANSI fallback for invalid UTF-8. Manual encoding
selection changes the interpretation of the existing byte source, not the
underlying file or the viewer's streaming guarantees.

## Scope

- Use consistent automatic encoding-detection semantics across the viewer,
  content search, editor, and Quick View.
- Make the supported legacy code pages available on every target platform.
- Detect encoding from a bounded sample, not from the full file.
- Keep binary detection available to the viewer so binary-looking files still open in hex.
- Add a viewer encoding mode:
  - automatic detection;
  - explicit encoding by code page/name.
- Add a small catalog of encodings for manual selection:
  - automatic detection;
  - UTF-8;
  - UTF-8 with BOM label when detected, but manual UTF-8 should not require a BOM;
  - UTF-16 LE;
  - UTF-16 BE;
  - Windows ANSI code page for the current culture;
  - Windows-1251;
  - Windows-1252;
  - CP866.
- Provide a viewer command that opens a modal encoding picker and applies the selected
  encoding immediately. The viewer keyboard shortcuts for encoding selection are defined
  by IDD-0052.
- Keep the selected encoding mode for the current viewer session without
  persisting a per-file or application default.
- Rebuild decoding-dependent lines, indexes, search results, and cached
  presentation so no stale information from the previous encoding is reused.
- Preserve the text/hex view mode when possible:
  - text stays text;
  - hex stays hex;
  - selecting an explicit text encoding from hex switches to text.
- Preserve approximate position across encoding changes using the current byte
  offset and a valid line start under the newly selected encoding.
- Show the active encoding in the viewer header for text mode.
- Content search, editor, and Quick View retain the same automatic-detection
  rules for text they decode.
- Any editor/Quick View size limits remain separate and do not restrict F3.

## Non-goals

- Restoring the old in-memory F3 viewer path.
- Reading the whole file to auto-detect encoding.
- Per-file remembered encoding.
- Persisting default viewer encoding in application settings in this spec.
- Manual encoding selection in the editor.
- A Quick View encoding selection UI.
- Search dialog code page selection beyond the existing automatic mode.
- Full charset detection by statistics or external libraries.
- Perfect recovery from arbitrary damaged byte streams.
- Hex editing or binary search.

## Acceptance criteria

- F3 still uses the streaming viewer for every file.
- Opening a huge text file reads only bounded byte samples and visible line ranges before
  the first render.
- Automatic detection is consistent across viewer, content search, editor,
  and Quick View.
- BOM detection handles UTF-8, UTF-16 LE, and UTF-16 BE.
- UTF-16-looking files without BOM remain readable in the viewer.
- Valid UTF-8 without BOM is detected as UTF-8.
- Invalid UTF-8 falls back to the Windows ANSI code page for the current culture, not
  silently to a generic process-default encoding.
- Binary-looking files still open in hex mode by default.
- The viewer header shows the active text encoding in text mode.
- The viewer provides a full encoding picker with automatic mode and the supported
  explicit encodings, accessible through the keyboard command defined in IDD-0052.
- Selecting an explicit encoding redraws the same file without restarting the application.
- Switching encoding clears stale decoding-dependent lines, indexes, search
  state, and cached presentation.
- Switching encoding preserves the streaming/path-based reader architecture and does not introduce a persistent viewer-lifetime file handle or full-file loading.
- Damaged byte sequences in text mode render with replacement characters or a clear
  status indication; they must not close the viewer.
- Control-character sanitizing from `IDD-0032` still applies after encoding changes.
- Editor and Quick View continue to use bounded text-reading paths.

## Verification

Focused automated checks:

- Automatic detection recognizes UTF-8 BOM, UTF-16 LE BOM, UTF-16 BE BOM,
  valid UTF-8 without BOM, invalid UTF-8 fallback, and binary-looking samples.
- Streaming text decoding correctly handles UTF-8, UTF-16 LE, UTF-16 BE,
  Windows-1251, Windows-1252, and CP866 fixtures with small read blocks.
- Selecting an encoding through the full viewer encoding picker changes displayed text
  for the same byte file without reopening it.
- The full picker is accessible using the shortcut defined in IDD-0052.
- Viewer text/hex toggling still works after manual encoding changes.
- Content search, editor, and Quick View use the same automatic detection
  results as the viewer for the same fixture bytes.

Manual checks:

1. Open a large UTF-8 log and switch between automatic and UTF-8.
2. Open a Windows-1251 file that is invalid UTF-8 and verify automatic fallback and manual
   Windows-1251 display.
3. Open a CP866 file and select CP866.
4. Open a binary file, confirm it starts in hex, select a text encoding, then switch back
   to hex with `H`.
5. Open a growing local log, enable `WATCH` and `TAIL`, and verify encoding selection preserves the live mode and correct tail rendering.
