# 0079 - Delete referenced items from search results

Related:
- 0010
- 0012
- 0013
- 0059
- 0078

## Goal

Allow `F8 Delete` on items shown in the search results panel. Deletion operates on the referenced underlying filesystem items and then reconciles the existing virtual result list without re-running the search.

## Effective intent

This document overrides only the conflicting `Delete` restrictions in `0012.spec-search-feature.md`, `0013.spec-dynamic-function-key-bar.md`, and `0078.spec-search-results-edit-referenced-items.md`. All other requirements remain effective.

1. The search results panel remains a virtual projection and is not a writable filesystem source in its own right.
2. `F8 Delete` is allowed for search results and deletes the referenced underlying items.
3. `PanelProviderCapabilities.SearchResults` includes `Delete`.
4. Search results still do not allow creating files or directories, renaming rows, moving items out of the panel, or copying/moving items into the panel.
5. Delete must use the referenced item locations, not the search-results panel location.
6. Local referenced items must use the normal local delete behavior, including the Recycle Bin when it is enabled and supported.
7. Multi-selection is supported.
8. When a selected directory contains another selected result, the physical delete request must avoid redundant descendant roots so deleting the parent does not cause a second delete attempt for its child.
9. After deletion, successfully deleted result rows must be removed from the current virtual result list. If a deleted directory has descendant rows in the current result list, those rows must also be removed when they no longer exist.
10. Search results must not automatically re-run the search after deletion. Explicit refresh continues to re-run the search as before.
11. On cancellation or partial failure, only result rows whose referenced paths are actually gone may be removed.
12. Cursor and scroll state must be normalized after rows are removed.
13. The function-key bar must advertise `F8 Delete` when the active search-results panel supports deletion, using the same capability check as command execution.

## Acceptance criteria

- `F8` on a file search result deletes the referenced file and removes the row from the current result list.
- `F8` on a directory search result deletes the referenced directory according to normal delete semantics and removes the deleted directory and any now-missing descendant rows from the current result list.
- Selected search results can be deleted in one operation.
- Selecting both a directory and a result below that directory does not issue redundant physical delete roots.
- Local search results honor the Recycle Bin setting when supported.
- Successful deletion does not re-run the search.
- Cancellation or partial failure preserves rows for referenced items that still exist.
- Cursor and scroll offsets remain valid after reconciliation.
- Create, rename, move-from, copy-to, and move-to remain unavailable for search results.
