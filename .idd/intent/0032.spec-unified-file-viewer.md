# 0032 - Unified File Viewer

Related:
- 0014
- 0016
- 0020

## Goal

Use one F3 viewer implementation for every file and let the user switch between text and
hex display modes.

## Context

Earlier viewer work introduced a streaming viewer for large files, but kept the
old in-memory `FileViewer` path for small text files. The current requirement removes that split:
viewing should always use the streaming byte reader, block cache, lazy scanner, and bounded
rendering path.

The viewer also needs an explicit display mode. Binary files should open as hex by
default, but every file must be viewable as text or as a 16-byte-per-row hex dump. Text
rendering must sanitize control characters before writing to the console so file content
cannot act as terminal control input/output.

Markdown files additionally have a presentation layer in text mode. Auto presentation may
hide deterministic Markdown decoration while keeping source text, source positions, search,
and rendering as separate concerns. Raw presentation always exposes the original source.

## Scope

- Route every F3 open through the streaming viewer.
- Remove the old in-memory viewer loop from `FileViewer`.
- Keep `TextFileReader` only for other existing users such as editor and Quick View.
- Add a viewer display mode state with text and hex modes.
- Default binary-looking files to hex and text-looking files to text.
- Add a keyboard command to toggle the current file between text and hex mode.
- Keep navigation, horizontal scrolling, jump, and follow behavior working in both modes.
- Support vertical text scrolling with the mouse wheel.
- Hide the physical terminal cursor while the viewer is active.
- Render text mode with sanitized control characters.
- Measure text-mode horizontal offsets, wrapping, clipping, search-match placement,
  and header fitting in terminal cells. Source search positions remain source-text
  UTF-16 positions and are translated only at the rendered text boundary,
  including after tab expansion and control-character sanitization.
- Render hex mode as a 16-byte-per-row dump with printable ASCII preview only.
- For Markdown files in Auto presentation, support deterministic non-recursive inline
  presentation for `[label](destination)`, `**bold**`, `*italic*`, and inline code delimited
  by matching backtick runs. Images, underscore emphasis, nested/composable styles, malformed
  constructs, and other unsupported Markdown stay raw.
- Keep source-to-presentation mapping only for source fragments that remain visible. Inline
  style spans use UTF-16 string positions; terminal-cell width remains a rendering concern.
- Apply Markdown inline presentation inside presented table cells before calculating their
  display widths, while continuing to use terminal-cell width for table layout.
- Search remains source-based. Search highlighting has visual priority over Markdown styles;
  if a match exists only in Markdown source hidden by presentation, render that line raw so
  the match remains visible and highlightable.
- F5 switches Markdown presentation between Auto and Raw without modifying source/scanner
  state. Raw lines carry no Markdown style spans.
- Keep Markdown presentation bounded and fail-safe for large files. Inline parsing must be
  linear or near-linear in the processed line and must not introduce pathological repeated
  rescans of delimiter-heavy input.
- Update tests and README.

## Non-goals

- Editing files in either mode.
- Search in the viewer.
- Persistent per-file mode settings.
- Changing Quick View behavior.
- Removing `TextFileReader` from editor or Quick View.
- A richer binary editor.
- Full CommonMark parsing, recursive inline Markdown, interactive links, images, headings,
  blockquotes, lists, or fenced-code rendering as part of inline Markdown presentation.

## Acceptance criteria

- F3 never calls the old in-memory `FileViewer` loop.
- Small and large files both use the streaming viewer path.
- Text-looking files open in text mode by default.
- Binary-looking files open in hex mode by default.
- The user can toggle the same file between text and hex mode.
- Control characters from file content are rendered as inert visible/safe characters or
  spaces, not sent to the console as controls.
- Viewer file reads are source-aware. Local files, writable non-local
  providers, and in-memory demo files are opened through the same panel-source
  read contract instead of requiring a real host filesystem path.
- Text-mode horizontal scrolling and wrapped lines preserve Unicode scalar boundaries,
  never render a partial wide character, and remain within the available terminal-cell
  viewport.
- A text search match is highlighted at the cells occupied by its rendered text,
  including when wide characters or expanded tabs precede it.
- Existing large-file navigation and follow behavior still work.
- The mouse wheel scrolls the visible file content vertically.
- The terminal cursor is hidden while the viewer is displayed.
- Quick View remains a bounded preview.
- Viewer find fields share the application field-history provider across viewer sessions and application restarts, while remaining isolated from editor find history.
- Markdown Auto presentation hides markers only for supported inline constructs and renders
  link, bold, italic, and inline-code semantic styles without changing the source line.
- Markdown Raw presentation shows the original source and no Markdown semantic styles.
- Markdown source/presentation mappings remain exact for visible source fragments, use UTF-16
  text coordinates, and do not fabricate mappings for hidden destinations or delimiters.
- Markdown table widths are calculated from transformed cell content using terminal-cell
  width, including wide Unicode.
- Search highlighting overrides Markdown semantic styling, and matches in hidden link
  destinations remain visible through raw-line fallback.
- Malformed, escaped, and unsupported Markdown does not lose source text and does not prevent
  independent supported constructs later on the same line from being presented.
- Markdown delimiter-heavy input does not introduce obvious quadratic behavior, and existing
  viewer presentation limits/fail-safe fallback remain effective.

## Verification

- Open a file in the viewer and verify that its active frame hides the terminal cursor.
- Open a Markdown file containing bold, italic, inline code, and a link; verify Auto hides the
  supported markers, F5 Raw restores the exact source, search highlighting wins over semantic
  styling, and searching a hidden link destination falls back to the raw line.
