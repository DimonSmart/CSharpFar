# IDD-0083 - User menu specification

Related:
- IDD-0001 (file manager and demo-mode isolation)
- IDD-0017 (normal command execution)
- IDD-0061 (separate native plugin registration system)

## Goal

Provide a configurable user menu for frequently used commands. Menu items
run through CSharpFar's normal command execution path, using the panel context
captured when the user menu is invoked. This specification describes the
currently implemented user menu, not the separately registered Plugins menu.

## Access and command execution

- `F2` opens the user menu. `Options -> User menu...` opens its editor.
- The execution menu displays each available item's title, in persisted order.
  Selecting an item executes it; cancelling the selection runs nothing.
- Only items applicable to the current runtime platform are displayed. If no
  items remain after filtering, show a message explaining that the user menu is
  empty and pointing to `Options -> User menu...`.
- A menu item has a required, nonblank `Title`, an optional `Command`, and an
  optional platform restriction. The item editor trims the title and rejects
  an empty or whitespace-only title.
- If `Command` is omitted, null, empty, or whitespace-only, execute `Title`.
  Otherwise execute the explicit command. Saving normalizes absent, blank,
  or exactly title-equal commands to an omitted command field. A distinct
  explicit command is preserved without trimming its leading/trailing spaces.
- The editor's list presents the title alone when it is also the effective
  command; otherwise it presents the title followed by its effective command.
- Expand placeholders in the effective command before dispatching it through
  the same application command handling used by the command line (including
  built-in and shell command handling). Do not introduce a second executor.
- A user-menu command obeys the execution restrictions of the running
  application, including demo mode. Merely opening the menu does not bypass
  the normal shell or filesystem restrictions.

## Panel-context placeholders

Expansion uses the committed active and passive panel locations, current
item, and selection resolved when the menu is invoked. If the relevant panel
locations are inconsistent with the committed UI state, do not construct
arguments or execute a command using stale panel data.

Supported tokens are literal, case-sensitive text substitutions:

| Token | Replacement |
| --- | --- |
| `{current}` | Full path of the current non-parent item; empty when there is no such item |
| `{selected}` | Selected full paths joined with spaces, each surrounded by double quotes; when selection is empty, a double-quoted current path, or empty when no current item exists |
| `{panelDir}` | Committed current directory of the active panel |
| `{otherPanelDir}` | Committed current directory of the inactive panel |

- Apply the same token expansion whether the effective command originates in
  `Title` or an explicit `Command`.
- `{current}`, `{panelDir}`, and `{otherPanelDir}` insert raw path text;
  `{selected}` adds double quotes around each selected path. The expander
  does not implement shell-specific escaping. Templates requiring argument
  quoting must supply it; do not claim all paths are safely shell-escaped.
- Unrecognized placeholders are not part of this contract and are not
  interpreted by the user-menu expander.

## Runtime platform filtering

- The optional platform value is `Windows`, `macOS`, or `Linux`. Missing
  platform means "All platforms".
- Filter items only for runtime visibility. Loading, editing, and saving keep
  items for other platforms, preserving their order and platform values.
- An existing JSON item without a platform field remains available on every
  supported platform; do not require a migration.
- A new configuration provides three example commands, each restricted to its
  platform: open Explorer at `{panelDir}` on Windows, Finder via `open` on
  macOS, or the file manager via `xdg-open` on Linux.

## Menu editing

- The editor offers `Add`, `Edit`, `Delete`, `Up`, `Down`, and `Close`.
  `Add` and `Edit` use title, optional command, and platform fields.
- `Delete` requires confirmation. `Up` and `Down` reorder entries one position
  at a time and preserve that order when saved.
- Work with an editable copy while the dialog is open; the runtime menu is
  updated only after successful persistence.
- Closing the list editor with `Close` or `Esc` commits accumulated changes
  when the list has been modified; exiting without changes does not write.
  Cancelling an individual item form or deletion confirmation does not make
  that individual edit.
- An empty list is valid: a user may delete every item and save an empty menu.
  An existing empty configuration must not be replaced by the defaults.

## Configuration and failure behavior

- The user menu is stored in `user-menu.json` under the session's configured
  configuration directory, independent of the general settings file.
- The file contains an ordered JSON array with camel-case property names
  (`title`, optional `command` and `platform`). Null optional properties are
  omitted. Existing files are loaded without runtime platform filtering.
- When the file is missing, the initial menu is populated with the three
  platform-specific examples. Writing the initial file is best-effort; those
  defaults remain available in memory if the initial write fails.
- Explicit saves write a temporary file in the same directory and replace
  the destination only after serialization succeeds. Runtime menu items
  change only after a successful write, using a detached snapshot of the
  supplied entries. A failed save must retain the previous runtime snapshot
  and existing configuration.
- If an edit cannot be persisted due to an I/O, access, or security failure,
  show the failure and offer `Edit` (return to the editor with unsaved changes)
  or `Discard` (leave the persisted and runtime menu unchanged).
- Invalid JSON must not be silently overwritten by default menu entries.
  The current loader reports an invalid-data error; recovery UI and migration
  of malformed files are outside this specification.
- Demo-mode configuration remains isolated from the normal user's settings
  and files as defined by `IDD-0001`.

## Non-goals

- No separate user-menu scripting language, macro runtime, or command executor.
- No dynamic native-plugin registration through `user-menu.json`; plugin
  registration and menus are governed by `IDD-0061`.
- No automatic platform-specific quoting/escaping for raw path placeholders.
- No command categories, hierarchical user submenus, or cross-device sync.

## Acceptance criteria

1. `F2` shows the platform-appropriate items in persisted order; selecting an
   item dispatches the expanded effective command, and cancelling runs none.
2. A title-only entry executes the title. An explicit command overrides it.
   Blank and title-equal command values are normalized away upon save.
3. Each of the four documented placeholders expands from the captured,
   committed panel state; selected paths are double-quoted and the selected
   fallback uses the current item. Parent navigation entries do not become
   `{current}` paths.
4. Windows/macOS/Linux-specific entries are visible only on matching
   platforms. Entries without a platform field work everywhere, and saving
   on one platform preserves entries for the others.
5. Users can add, edit, confirm deletion, move items up/down, and save an
   empty menu. Item-form cancellation preserves the prior item.
6. The item editor validates title presence. Existing ordered items and
   platform restrictions survive saving and reopening.
7. A first run without `user-menu.json` offers the three platform-specific
   defaults. An existing empty file remains empty on subsequent runs.
8. Saving updates the runtime menu only when the file write succeeds. Save
   failures offer Edit/Discard, preserving the previous persisted and
   runtime menu until a save succeeds.
9. User-menu commands in demo mode do not bypass demo restrictions or use
   the normal user's configuration directory.

## Verification

- Extend or run `UserMenuStoreTests` for default creation, title fallback,
  explicit command, JSON normalization, ordering, detached snapshots, empty
  menus, malformed JSON, and failed-save preservation.
- Extend or run `UserMenuPlatformTests` for every supported platform,
  legacy JSON without platform, visibility filtering, saved cross-platform
  entries, and platform-only item edits.
- Verify `PlaceholderExpander` and panel operand handling with current item,
  parent item, zero/multiple selections, both panel directories, and a
  rejected stale committed location.
- Test the live `F2` selection and `Options -> User menu...` editor: Add,
  Edit, Delete-confirmation cancellation, Up/Down, title validation, `Esc`
  after edits, empty menu help, and the Edit/Discard save-error paths.
- Run a demo-mode scenario to verify invoking a shell command through the
  user menu cannot escape demo-mode process and file-system restrictions.
