## Goal

CSharpFar provides a first-party **Processes and Ports** module for diagnosing
local TCP and UDP endpoints and safely identifying or terminating the process
that blocks a required local port.

## Behavior

The Plugins menu exposes `Processes and Ports...`; the `ports` command opens
the same modal workflow, and `ports <filter>` pre-populates its filter. The
workflow initially includes TCP listeners and UDP endpoints, while other TCP
connections are opt-in.

Each visible row represents exactly one endpoint. It shows process, PID,
protocol, numeric local address, local port, and TCP state when applicable.
Rows sort by local port, protocol, local address, process name, PID, and state.
The case-insensitive invariant filter operates only on the captured snapshot
and matches process name, PID, executable path, protocol, addresses, ports,
and state. It never causes DNS lookups or a fresh OS query.

Details show the selected process and every endpoint for that process from the
same snapshot. Missing process metadata does not hide endpoints. Refresh
captures a new best-effort snapshot and preserves the selected endpoint when
possible.

Terminating a process requires confirmation. CSharpFar never terminates itself,
uses a process identity that includes process start time to reject reused PIDs,
and refreshes after successful termination. Demo sessions display deterministic
data and never inspect or terminate real processes. Unsupported hosts explain
that the feature is unavailable and do not run shell fallbacks.

The module is a native first-party module, not a file-panel source. Platform
collection and termination are isolated behind the platform-services boundary;
UI and module code contain neither platform probes nor P/Invoke.

## Non-goals

This is not a task manager: it does not expose all processes, resource usage,
trees, services, windows, process priorities, or process-tree termination. It
does not poll automatically, resolve DNS, launch `netstat`, PowerShell, `ss`,
or `lsof`, or implement Linux/macOS endpoint collection.

## Acceptance criteria

1. A user can find the owner of a local TCP or UDP port through the menu or
   `ports` command, including IPv4 and IPv6 endpoints.
2. Filtering and refresh remain responsive without repeated platform reads
   during rendering.
3. Details, access errors, stale identities, process exit races, and empty
   results are understandable and do not crash the application.
4. Termination is explicit, safe against self-termination and PID reuse, and
   unavailable without real side effects in demo mode.
5. The dialog follows shared modal, scrolling, focus, input-routing, and
   resize lifecycle rules.

## Verification

Automated verification covers a Windows loopback TCP listener, deterministic
filtering/sorting behavior, and termination safety and refresh behavior with a
fake service. Manual verification checks the command, TCP/UDP IPv4 and IPv6,
details, denied termination, demo data, and the unsupported Unix message.
