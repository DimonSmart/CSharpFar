# IDD-0036 - Application icon specification

Related:
- IDD-0001 (CSharpFar product identity)
- IDD-0077 (macOS application bundle and its derived icon)

## Goal and scope

CSharpFar has a recognizable, original application icon that communicates
its two-panel console file-manager identity without copying Far Manager
branding. On Windows, the icon must appear on the **final runnable CSharpFar
host executable** and be available to Windows shell surfaces, including
file browsing and application/task-switching presentations.

This document governs the shared product artwork and the Windows executable
icon. IDD-0077 separately governs the icon resource and packaging inside
the macOS `CSharpFar.app` bundle.

## Product artwork and integration

- Maintain an original icon design that is high-contrast and legible at
  typical small application-icon sizes. It may evoke a two-panel
  console file manager but must not reproduce Far Manager's icon,
  logo or trademarked artwork.
- Keep the editable/source artwork alongside an appropriate multi-size
  Windows `.ico` derivative in the repository. The distributed Windows
  executable must embed that icon as its application icon resource.
- The build/package boundary responsible for embedding the Windows icon
  is the **runnable Windows host**, not the cross-platform application
  library. The icon is visible on the actual `CSharpFar.exe` artifact
  delivered to Windows users.
- Other supported application packaging formats may derive platform
  icon sizes from the same original artwork. The macOS bundle's
  `.icns` resource and its Finder presentation remain owned by IDD-0077.
- Icon and packaging changes must not alter the console UI's theme,
  terminal rendering, shortcuts or file-manager behavior.

## Non-goals

- Far Manager trademark/brand imitation or copying its assets.
- File associations, installer branding, shortcut creation or new
  packaging workflows as a consequence of defining the Windows icon.
- Requiring the shared application library or reusable UI assemblies
  to embed an executable icon resource.
- Adding runtime drawing or an extra GUI shell merely to display the icon.

## Acceptance criteria

1. The repository contains the original vector/source artwork and
   a Windows `.ico` derivative appropriate for executable embedding.
2. The packaged Windows host executable exposes the CSharpFar icon
   resource, and it is visible in normal Windows shell/task surfaces.
3. The product's icon identity remains consistent with the macOS
   application bundle defined in IDD-0077, without prescribing
   platform-specific icon generation details here.
4. No file-manager behavior, terminal output or reusable library
   packaging is coupled to Windows icon resource configuration.

## Verification

Check that the Windows host build configuration embeds the icon in the
**host executable**, rather than requiring it on the application library.
Inspect the resulting Windows executable's icon resource and its
appearance in Explorer and a Windows task-switching/application surface.
Verify that the artwork remains identifiable at small sizes, and that
macOS packaging can derive its bundle icon from the same source asset.
