# 0014 - Quick View Panel

Related:
- none

## Goal

Provide an enhanced Quick View panel (Ctrl+Q) that shows rich, context-aware previews of
the currently selected item in the opposite panel — including full directory details with
asynchronous size calculation and text file metadata at the bottom. When directory
monitoring is enabled, that directory becomes a pinned Quick View monitoring root until
monitoring is disabled.

## Context

The original Quick View showed only a file's text content or a one-line directory summary.
Users need richer information without opening a full viewer: directory stats, BOM / EOL type,
and the associated application — all without blocking the UI. A monitored directory also acts
as a temporary working set: recent filesystem changes can be inspected sequentially in the
ordinary file panel without losing the monitoring view or its history.

## Scope

### Panel frame and styling
- Double-line border (`╔═╗║╚╝`) matching the style of regular panels.
- Same colors as an active panel (`PanelBorderActiveFg`, `NormalFileFg`, `PanelTitleFocusedFg`).
- The active panel retains its own view mode (Full / Brief) while Quick View is active.
- In directory-monitor view, the monitor toggle and visible recent-change rows participate in
  the shared routed pointer interaction model. Clicking the monitor row toggles monitoring
  without changing the active panel or passing the event to an underlying panel. Clicking a
  navigable visible row activates that exact entry; clicking a deleted or unavailable entry
  leaves panels unchanged.

### Directory view
- Full path, creation / modification / access timestamps.
- Count of files and direct subdirectories (top level only, synchronous).
- Total size computed asynchronously in a background task:
  - In normal Quick View, starts when the cursor moves to a directory and is cancelled and
    restarted when the cursor moves to a different item.
  - While monitoring is enabled, panel cursor movement does not replace the monitored
    directory or cancel its scan; the monitoring root is pinned.
  - Progress is throttled and background updates reliably wake the UI.
  - Intermediate display: `<size>  (scanning…)`, final: `<size>`.
  - Access errors collected and displayed below `Errors: N` in a dark-yellow style.
- File attributes (ReadOnly, Hidden, System, Archive, Compressed, Encrypted).
- A directory Quick View can enable an opt-in monitor for the selected directory and its
  descendants. Monitoring is off by default. Enabling it pins that directory as the
  `MonitoringRoot`; no separate pause/fix-folder setting exists.
- While monitoring is enabled, Quick View continues to render `MonitoringRoot` regardless of
  active-panel navigation, including navigation initiated from `Recent changes`. The watcher,
  directory summary, retained history, selection, and logical viewport remain associated with
  that root.
- While monitoring, the view retains a bounded newest-first history of created, modified,
  renamed, and deleted filesystem changes, using paths relative to the monitored directory
  where possible. Renames show both the previous and new path. Repeated modified events for
  the same local-filesystem path share one retained modified entry regardless of their timing
  or intervening history entries. The entry retains its identity, records the time of its most
  recent event and a repeat count, and moves to the newest position. A single modification
  displays `M`; repeated modifications display `M×N`. Created, deleted, and renamed events
  remain distinct, and a rename never transfers a modified entry or its repeat count from its
  old path to its new path. History path equality follows the platform local-filesystem case
  semantics.
- The monitor retains at most 256 logical recent-change entries. Its newest-first retained
  history is independent of the available panel height. The `Recent changes` area is the only
  scrollable part of Quick View: it renders a viewport of that history after directory details,
  the monitor toggle, and visible scan errors. A resize changes the viewport capacity but never
  removes retained entries. When no entry fits, the heading may be shown without entries or
  omitted.
- Scrolling uses the shared routed scrollable-list and scrollbar infrastructure. Mouse wheel
  over `Recent changes`, including at either boundary, is consumed by Quick View and never
  scrolls the underlying file panel. The list and scrollbar operate on the same state.
  Ctrl+Up/Down moves by an entry and Ctrl+PageUp/PageDown moves by a page. Unmodified
  Up/Down/PageUp/PageDown continue to control the active file panel.
- The history selection is a `DirectoryChange.Id`, not a screen row or list index, and
  navigation operates over the whole retained history. Keyboard navigation keeps the selected
  entry visible. After mouse scrolling, selection is normalized to a visible entry before it
  can be activated. The committed Quick View frame records the history viewport, its bounds,
  displayed entry identities, selection, and scrollbar hit-test geometry; input uses that
  frame rather than recalculating layout.
- When older history is being viewed, unrelated new changes preserve the displayed logical
  anchor rather than returning the viewport to newest. Resize preserves the selected identity
  and logical viewing position where possible.
- A Changed event for the same path received within one second of its original Created event
  is absorbed into that Created entry. The Created identity, kind, and repeat count remain
  unchanged, its timestamp may advance, and the fixed one-second window does not slide. Path
  equality uses local-filesystem semantics. This Created-to-Changed absorption precedes
  existing Changed-event coalescing; deleted and renamed events are never absorbed.
- A detected change refreshes the directory summary asynchronously while retaining the last
  valid summary and visibly indicating that it is updating. Monitor-triggered refreshes do not
  publish intermediate scan totals: the displayed completed summary remains stable until the
  refresh completes, then changes atomically to its new completed result. Initial directory
  scans continue to display their intermediate progress. The displayed total remains derived
  from a complete directory scan, not from accumulated change events.
- Monitoring handles duplicate, burst, and missed watcher events best-effort: it coalesces
  refreshes without concurrent scans and requests another scan when a change occurs during one.
  A watcher error must not close or crash Quick View and causes a summary refresh.
- Disabling monitoring stops the watcher and removes the pin, but does not clear the current
  in-memory monitoring snapshot. Retained entries keep their IDs, timestamps, repeat counts,
  and rename information. Selection and logical scroll state are preserved where possible.
  If normal Quick View later selects the same directory, the retained history may be rendered
  as a read-only snapshot with no watcher running. Re-enabling monitoring for that same
  directory continues the snapshot. Enabling monitoring for a different directory may replace
  the retained snapshot. No persistent storage or multi-directory history is required.
- After monitoring is disabled, Quick View immediately resumes its ordinary
  follow-current-selection behavior. If the active panel currently selects a file reached from
  `Recent changes`, that file becomes the Quick View preview.
- A visible recent created, modified, or renamed entry whose current target still exists can be
  activated by clicking it or by selecting it and pressing Ctrl+Enter. Primary click and
  Ctrl+Enter use one activation workflow identified by that entry's `DirectoryChange.Id`.
  Created and modified entries use their current path; renamed entries use their new path.
  Deleted entries cannot be activated.
- If the active ordinary local/source file panel can open the target, activation opens the
  target's parent directory and selects the target. Quick View stays open, monitoring stays
  enabled, `MonitoringRoot` stays unchanged, retained history is preserved, and another entry
  can be activated immediately. The target panel watcher may be restarted for its new location.
  Special panel modes are never replaced automatically. Missing and deleted targets leave the
  panel, Quick View, and monitoring session unchanged.
- Normal file-panel navigation, including navigation caused by a recent-change activation, is
  not a monitoring-session termination condition. The active monitoring session ends when the
  user disables monitoring, Quick View closes, the owning panel closes, the application exits,
  or Quick View enters an incompatible mode. Disabling monitoring and disposing its controller
  remain barriers against stale callbacks: old watcher callbacks and scans cannot add history,
  start a new scan, update the summary, or mutate a later monitoring session.
- Enter, Ctrl+Enter, and Ctrl+M are distinct Quick View operations: plain Enter does not toggle
  monitoring; Ctrl+M and a primary-pointer click on the full monitor-toggle row invoke the same
  directory-monitor toggle operation; Ctrl+Enter only activates the selected visible
  recent-change entry.

### Text file view
- File content displayed in the upper portion.
- A horizontal separator line (`╟──[ AppName ]──╢`) at the bottom, with the name of the
  associated Windows application (from registry `HKCR\<ext>\shell\open\command`) centred.
- Below the separator: one info row showing `BOM: <value>  EOL: <value>`.
  - BOM values: `UTF-8`, `UTF-16 LE`, `UTF-16 BE`, `UTF-32 LE`, `UTF-32 BE`, `No`.
  - EOL values: `Windows (CRLF)`, `Unix (LF)`, `Classic Mac (CR)`, `Mixed`.
- Info section only shown when the panel has more than 3 visible rows.
- Recognised text extensions: ~70 common types including source code, markup, config,
  script, and data formats (see `TextFileInfo.TextExtensions`).

### Async correctness
- Replacing cancellation state must not lose refresh signals when the current background
  operation is cancelled.

## Non-goals

- Scrolling Quick View content generally; only the `Recent changes` viewport scrolls.
- Binary file preview.
- Editable Quick View.
- Persistent or multi-directory monitor history, filesystem audit logging, incremental
  directory-size accounting, or recovery/navigation for deleted entries.
- A separate `Pause` or `Fix monitoring folder` user mode.
- Cross-platform registry fallback for associated apps.
- Recursive first-level file / subdirectory counts (only top level).

## Acceptance criteria

- Ctrl+Q shows the opposite panel as Quick View; active panel keeps its view mode.
- Selecting a directory shows path, timestamps, file/dir counts, async total size, attributes.
- In normal Quick View, moving to another item cancels the previous directory-size scan and
  Quick View follows the active-panel selection.
- Directory monitoring is off until explicitly enabled. Enabling it pins the current directory
  as `MonitoringRoot`; moving the active-panel cursor does not replace the Quick View while
  monitoring remains enabled.
- When enabled, filesystem changes throughout the monitoring root appear in a bounded
  newest-first history of at most 256 logical entries and trigger an eventual refreshed
  complete directory summary without parallel scans. All retained entries are reachable
  through the `Recent changes` viewport.
- A same-path Changed event within one second of a Created event is represented by the original
  Created entry; later Changed events retain the existing Changed coalescing behavior.
- A monitor-triggered rescan keeps the previous completed summary visible until it completes
  and publishes only its new completed result; the initial scan of a newly selected directory
  continues to show scanning progress.
- Primary click and Ctrl+Enter on an existing created, modified, or renamed target navigate the
  active ordinary local/source file panel to its parent and select it without closing Quick
  View, disabling monitoring, changing `MonitoringRoot`, or clearing history. Multiple entries
  can be activated sequentially.
- Deleted or unavailable targets and special panels are left unchanged; Quick View and the
  monitoring session remain usable.
- Disabling monitoring stops the watcher, retains the current in-memory history snapshot, and
  immediately returns Quick View to follow-current-selection behavior. Re-selecting the former
  monitoring directory may display that snapshot while monitoring is off; re-enabling the same
  directory continues it. Enabling another directory may replace it.
- Mouse wheel over `Recent changes` changes that list's viewport/selection as appropriate, is
  consumed even at the top or bottom boundary, shares state with its scrollbar, and does not
  reach the underlying panel. Mouse wheel outside that region gains no new behavior.
- Plain Enter, Ctrl+M, and Ctrl+Enter remain separate: Ctrl+M and a mouse click on the monitor
  row toggle monitoring, and Ctrl+Enter activates only the selected recent-change entry.
- Stale monitor callbacks after disable/dispose cannot start a directory scan, append history,
  or publish Quick View state into a later session.
- For text files, separator line shows associated app name; info row shows BOM and EOL.
- `BOM: No` shown when there is no BOM (not "No BOM").
- Errors during size scan shown in dark-yellow below the error count.
- No UI freeze while size is being computed.

## Verification

Manual: open a directory in Quick View, enable monitoring, create/modify several files, and
use mouse wheel, Ctrl+Up/Down, Ctrl+PageUp/PageDown, and the scrollbar to inspect more than one
viewport of recent changes. Confirm wheel never scrolls the underlying panel and remains
consumed at the history boundaries. Activate several existing entries sequentially by mouse
and Ctrl+Enter: the ordinary file panel must move to each target while Quick View remains on
the original monitoring root and continues collecting new changes. Confirm deleted, missing,
and special-panel targets do nothing.

Manual: after navigating to a recent-change target, disable monitoring. Confirm the watcher
stops and Quick View immediately previews the current active-panel item. Return to the original
directory and confirm the previous history snapshot is still available; re-enable monitoring
and confirm it continues. Close Quick View and confirm the in-memory monitoring session is
cleaned up.

Automated: cover the 256-entry logical history bound; Created-to-Changed absorption, stable
identity and fixed time window; preserved Changed-to-Changed coalescing; pinned monitoring root;
sequential activation without Quick View closure; disable-to-follow behavior; retained history
and same-root resume; different-root replacement; wheel routing and boundary consumption;
scrollbar/shared state; deleted/missing/special-panel activation failure; and stale callback
barriers after disable/dispose. Preserve existing coverage for initial/monitor scan progress,
logical anchor behavior, resize, and committed-frame input geometry.
