# 0014 - Quick View Panel

Related:
- none

## Goal

Provide an enhanced Quick View panel (Ctrl+Q) that shows rich, context-aware previews of
the currently selected item in the opposite panel — including full directory details with
asynchronous size calculation and text file metadata at the bottom.

## Context

The original Quick View showed only a file's text content or a one-line directory summary.
Users need richer information without opening a full viewer: directory stats, BOM / EOL type,
and the associated application — all without blocking the UI.

## Scope

### Panel frame and styling
- Double-line border (`╔═╗║╚╝`) matching the style of regular panels.
- Same colors as an active panel (`PanelBorderActiveFg`, `NormalFileFg`, `PanelTitleFocusedFg`).
- The active panel retains its own view mode (Full / Brief) while Quick View is active.
- In directory-monitor view, the monitor toggle and visible recent-change rows
  participate in the shared routed pointer interaction model. Clicking the
  monitor row toggles monitoring without changing the active panel or passing
  the event to an underlying panel. Clicking a navigable visible row activates
  that exact entry; clicking a deleted or unavailable entry leaves panels
  unchanged.

### Directory view
- Full path, creation / modification / access timestamps.
- Count of files and direct subdirectories (top level only, synchronous).
- Total size computed asynchronously in a background task:
  - Starts when the cursor moves to a directory.
  - Cancelled and restarted when the cursor moves to a different item.
  - Progress is throttled and background updates reliably wake the UI.
  - Intermediate display: `<size>  (scanning…)`, final: `<size>`.
  - Access errors collected and displayed below `Errors: N` in a dark-yellow style.
- File attributes (ReadOnly, Hidden, System, Archive, Compressed, Encrypted).
- A directory Quick View can enable an opt-in monitor for the selected directory and
  its descendants. Monitoring is off by default and is scoped to that Quick View
  directory.
- While monitoring, the view retains a bounded newest-first history of created,
  modified, renamed, and deleted filesystem changes, using paths relative to the
  monitored directory where possible. Renames show both the previous and new path.
  The number of recent changes displayed is determined by the vertical space
  remaining after directory details, the monitor toggle, and visible scan errors;
  it has no fixed UI limit and never overflows the Quick View bounds. A resize
  changes only the displayed capacity, not the retained history. If no entry fits,
  the recent-changes heading may be shown without entries or omitted.
- A detected change refreshes the directory summary asynchronously while retaining
  the last valid summary and visibly indicating that it is updating. The displayed
  total remains derived from a complete directory scan, not from accumulated change
  events.
- Monitoring handles duplicate, burst, and missed watcher events best-effort: it
  coalesces refreshes without concurrent scans and requests another scan when a
  change occurs during one. A watcher error must not close or crash Quick View and
  causes a summary refresh.
- The monitor stops when it is disabled, the Quick View selection changes, Quick
  View leaves directory mode or closes, its owning panel closes, or the application
  exits. Stale callbacks and scans must not update a later Quick View session.
- A visible recent created, modified, or renamed entry whose current target still
  exists can be activated by clicking it or by selecting it and pressing
  Ctrl+Enter. Selection and keyboard navigation are constrained to visible entries;
  when a resize hides the selected entry, selection moves to the last visible entry
  or is cleared when none is visible. Activation always applies to that specific
  entry: created and modified entries use their current path, while renamed entries
  use their new path. Deleted entries cannot be activated. If the active panel is
  in ordinary local/source file-panel mode, it opens the target's parent directory
  and selects the target. Deleted entries do not navigate; special panel modes are
  never replaced automatically. A missing target leaves the panel unchanged.
- Enter, Ctrl+Enter, and Ctrl+M are distinct Quick View operations: plain Enter
  does not toggle monitoring; Ctrl+M and a primary-pointer click on the full
  monitor-toggle row invoke the same directory-monitor toggle operation;
  Ctrl+Enter only activates the selected visible recent-change entry.

### Text file view
- File content displayed in the upper portion.
- A horizontal separator line (`╟──[ AppName ]──╢`) at the bottom, with the name of the
  associated Windows application (from registry `HKCR\<ext>\shell\open\command`) centred.
- Below the separator: one info row showing `BOM: <value>  EOL: <value>`.
  - BOM values: `UTF-8`, `UTF-16 LE`, `UTF-16 BE`, `UTF-32 LE`, `UTF-32 BE`, `No`.
  - EOL values: `Windows (CRLF)`, `Unix (LF)`, `Classic Mac (CR)`, `Mixed`.
- Info section only shown when the panel has more than 3 visible rows.
- Recognised text extensions: ~70 common types including source code, markup, config,
  script, and data formats (see `TextFileInfo.TextExtensions`).

### Async correctness
- Replacing cancellation state must not lose refresh signals when the current
  background operation is cancelled.

## Non-goals

- Scrolling inside Quick View.
- Binary file preview.
- Editable Quick View.
- Persistent directory-monitor history, filesystem audit logging, incremental
  directory-size accounting, or recovery/navigation for deleted entries.
- Cross-platform registry fallback for associated apps.
- Recursive first-level file / subdirectory counts (only top level).

## Acceptance criteria

- Ctrl+Q shows the opposite panel as Quick View; active panel keeps its view mode.
- Selecting a directory shows path, timestamps, file/dir counts, async total size, attributes.
- While scanning, size shows current partial value with `(scanning…)` suffix.
- On completion, `(scanning…)` disappears.
- Moving to another item cancels the previous size scan immediately.
- Directory monitoring is off until explicitly enabled and has no recursive
  watching or periodic scans while disabled.
- When enabled, filesystem changes throughout the selected directory tree appear
  in a bounded newest-first history and trigger an eventual refreshed complete
  directory summary without parallel scans. The view shows as many newest entries
  as fit after summary information, monitor control, and errors, with no scrolling
  or overflow. UI coalescing of repeated change rows does not suppress a summary
  refresh, and changes received during a scan cause a later scan after the current
  scan completes.
- Activating an existing created, modified, or renamed target navigates only the
  active ordinary local/source file panel to the target's parent and selects it;
  deleted or unavailable targets and special panels are left unchanged.
- Plain Enter, Ctrl+M, and Ctrl+Enter remain separate: Ctrl+M and a mouse click
  on the monitor row toggle monitoring, and Ctrl+Enter activates only the selected
  visible recent-change entry.
- Leaving the monitored directory Quick View stops monitoring and prevents its
  pending work from changing a new view.
- For text files, separator line shows associated app name; info row shows BOM and EOL.
- `BOM: No` shown when there is no BOM (not "No BOM").
- Errors during size scan shown in dark-yellow below the error count.
- No UI freeze while size is being computed.

## Verification

Manual: open a large directory in Quick View and navigate away before scan completes —
the scan must stop; a new one must start for the new directory.

Manual: enable directory monitoring, create, modify, rename, and delete entries
below the selected directory, and confirm recent changes, summary refresh, and
safe cleanup when leaving Quick View. Resize the terminal to confirm that the
visible newest-first list grows and shrinks without losing retained history,
overflowing the Quick View, or allowing selection of hidden entries. During a
burst, including changes that arrive while a scan is active, confirm the summary
settles to the last filesystem state without overlapping scans. Click the full
monitor row to toggle monitoring without changing the active panel, then click and
keyboard-select visible created, modified, and renamed rows and confirm each opens
its own target in the active ordinary file panel; confirm deleted, missing, and
special-panel cases leave panels unchanged.
