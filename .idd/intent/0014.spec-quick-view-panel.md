# 0014 - Quick View Panel

Related:
- none

## Goal

Provide an enhanced Quick View panel (Ctrl+Q) that shows rich, context-aware previews of
the currently selected item in the opposite panel — including full directory details with
asynchronous size calculation and text file metadata at the bottom.

## Context

The original Quick View showed only a file's text content or a one-line directory summary.
Users need richer information without opening a full viewer: directory stats, BOM / EOL type,
and the associated application — all without blocking the UI.

## Scope

### Panel frame and styling
- Double-line border (`╔═╗║╚╝`) matching the style of regular panels.
- Same colors as an active panel (`PanelBorderActiveFg`, `NormalFileFg`, `PanelTitleFocusedFg`).
- The active panel retains its own view mode (Full / Brief) while Quick View is active.
- In directory-monitor view, the monitor toggle and visible recent-change rows
  participate in the shared routed pointer interaction model. Clicking the
  monitor row toggles monitoring without changing the active panel or passing
  the event to an underlying panel. Clicking a navigable visible row activates
  that exact entry; clicking a deleted or unavailable entry leaves panels
  unchanged.

### Directory view
- Full path, creation / modification / access timestamps.
- Count of files and direct subdirectories (top level only, synchronous).
- Total size computed asynchronously in a background task:
  - Starts when the cursor moves to a directory.
  - Cancelled and restarted when the cursor moves to a different item.
  - Progress is throttled and background updates reliably wake the UI.
  - Intermediate display: `<size>  (scanning…)`, final: `<size>`.
  - Access errors collected and displayed below `Errors: N` in a dark-yellow style.
- File attributes (ReadOnly, Hidden, System, Archive, Compressed, Encrypted).
- A directory Quick View can enable an opt-in monitor for the selected directory and
  its descendants. Monitoring is off by default and is scoped to that Quick View
  directory.
- While monitoring, the view retains a bounded newest-first history of created,
  modified, renamed, and deleted filesystem changes, using paths relative to the
  monitored directory where possible. Renames show both the previous and new path.
  Repeated modified events for the same local-filesystem path share one retained
  modified entry regardless of their timing or intervening history entries. The
  entry retains its identity, records the time of its most recent event and a
  repeat count, and moves to the newest position. A single modification displays
  `M`; repeated modifications display `M×N`. Created, deleted, and renamed events
  remain distinct, and a rename never transfers a modified entry or its repeat
  count from its old path to its new path. History path equality follows the
  platform local-filesystem case semantics.
  The monitor retains at most 256 logical recent-change entries. Its newest-first
  retained history is independent of the available panel height. The `Recent changes`
  area is the only scrollable part of Quick View: it renders a viewport of that
  history after directory details, the monitor toggle, and visible scan errors.
  A resize changes the viewport capacity but never removes retained entries.
  When no entry fits, the heading may be shown without entries or omitted.
  Scrolling uses the shared routed scrollable-viewport and scrollbar infrastructure.
  Mouse wheel over this area, including at either boundary, is consumed by Quick
  View; Ctrl+Up/Down moves by an entry and Ctrl+PageUp/PageDown moves by a page.
  Unmodified Up/Down/PageUp/PageDown continue to control the active file panel.
  The history selection is a `DirectoryChange.Id`, not a screen row or list index,
  and navigation operates over the whole retained history. Keyboard navigation keeps
  the selected entry visible. After mouse scrolling, selection is normalized to a
  visible entry before it can be activated. The committed Quick View frame records
  the history viewport, its bounds, displayed entry identities, selection, and any
  scrollbar hit-test geometry; input uses that frame rather than recalculating layout.
  When older history is being viewed, unrelated new changes preserve the displayed
  logical anchor rather than returning the viewport to newest. Resize preserves the
  selected identity and logical viewing position where possible.
  A Changed event for the same path received within one second of its original
  Created event is absorbed into that Created entry. The Created identity, kind, and
  repeat count remain unchanged, its timestamp may advance, and the fixed one-second
  window does not slide. Path equality uses local-filesystem semantics. This
  Created-to-Changed absorption precedes existing Changed-event coalescing; deleted
  and renamed events are never absorbed.
- A detected change refreshes the directory summary asynchronously while retaining
  the last valid summary and visibly indicating that it is updating. Monitor-triggered
  refreshes do not publish intermediate scan totals: the displayed completed summary
  remains stable until the refresh completes, then changes atomically to its new
  completed result. Initial directory scans continue to display their intermediate
  progress. The displayed total remains derived from a complete directory scan, not
  from accumulated change events.
- Monitoring handles duplicate, burst, and missed watcher events best-effort: it
  coalesces refreshes without concurrent scans and requests another scan when a
  change occurs during one. A watcher error must not close or crash Quick View and
  causes a summary refresh.
- The monitor stops when it is disabled, the Quick View selection changes, Quick
  View leaves directory mode or closes, its owning panel closes, or the application
  exits. Disabling monitoring and disposing its Quick View controller are barriers:
  a concurrent stale monitor callback cannot start a new directory scan or mutate
  Quick View state after either operation returns. Stale callbacks and scans must
  not update a later Quick View session.
- A visible recent created, modified, or renamed entry whose current target still
  exists can be activated by clicking it or by selecting it and pressing
  Ctrl+Enter. Primary click and Ctrl+Enter use one activation workflow identified by
  that entry's `DirectoryChange.Id`. Activation always applies to that specific
  entry: created and modified entries use their current path, while renamed entries
  use their new path. Deleted entries cannot be activated. If the active panel is
  in ordinary local/source file-panel mode, it opens the target's parent directory
  and selects the target. A successful activation starts watching the target panel
  and closes Quick View through its normal lifecycle. Deleted entries do not
  navigate; special panel modes are never replaced automatically. A missing target
  leaves the panel unchanged and Quick View open.
- Enter, Ctrl+Enter, and Ctrl+M are distinct Quick View operations: plain Enter
  does not toggle monitoring; Ctrl+M and a primary-pointer click on the full
  monitor-toggle row invoke the same directory-monitor toggle operation;
  Ctrl+Enter only activates the selected visible recent-change entry.

### Text file view
- File content displayed in the upper portion.
- A horizontal separator line (`╟──[ AppName ]──╢`) at the bottom, with the name of the
  associated Windows application (from registry `HKCR\<ext>\shell\open\command`) centred.
- Below the separator: one info row showing `BOM: <value>  EOL: <value>`.
  - BOM values: `UTF-8`, `UTF-16 LE`, `UTF-16 BE`, `UTF-32 LE`, `UTF-32 BE`, `No`.
  - EOL values: `Windows (CRLF)`, `Unix (LF)`, `Classic Mac (CR)`, `Mixed`.
- Info section only shown when the panel has more than 3 visible rows.
- Recognised text extensions: ~70 common types including source code, markup, config,
  script, and data formats (see `TextFileInfo.TextExtensions`).

### Async correctness
- Replacing cancellation state must not lose refresh signals when the current
  background operation is cancelled.

## Non-goals

- Scrolling Quick View content generally; only the `Recent changes` viewport scrolls.
- Binary file preview.
- Editable Quick View.
- Persistent directory-monitor history, filesystem audit logging, incremental
  directory-size accounting, or recovery/navigation for deleted entries.
- Cross-platform registry fallback for associated apps.
- Recursive first-level file / subdirectory counts (only top level).

## Acceptance criteria

- Ctrl+Q shows the opposite panel as Quick View; active panel keeps its view mode.
- Selecting a directory shows path, timestamps, file/dir counts, async total size, attributes.
- While scanning, size shows current partial value with `(scanning…)` suffix.
- On completion, `(scanning…)` disappears.
- Moving to another item cancels the previous size scan immediately.
- Directory monitoring is off until explicitly enabled and has no recursive
  watching or periodic scans while disabled.
- When enabled, filesystem changes throughout the selected directory tree appear
  in a bounded newest-first history of at most 256 logical entries and trigger an
  eventual refreshed complete directory summary without parallel scans. All retained
  entries are reachable through the `Recent changes` viewport; only that area scrolls
  without overflow. UI coalescing of repeated change rows does not suppress a summary
  refresh or a UI wake, and changes received during a scan cause a later scan after
  the current scan completes. Repeating a selected modified entry keeps it selected
  as that same entry moves to the newest position.
- A same-path Changed event within one second of a Created event is represented by
  the original Created entry; later Changed events retain the existing Changed
  coalescing behavior.
- A monitor-triggered rescan keeps the previous completed summary visible until it
  completes and publishes only its new completed result; the initial scan of a newly
  selected directory continues to show scanning progress.
- Activating an existing created, modified, or renamed target by primary click or
  Ctrl+Enter navigates only the active ordinary local/source file panel to the
  target's parent, selects it, and closes Quick View through its normal lifecycle;
  deleted or unavailable targets and special panels are left unchanged.
- Plain Enter, Ctrl+M, and Ctrl+Enter remain separate: Ctrl+M and a mouse click
  on the monitor row toggle monitoring, and Ctrl+Enter activates only the selected
  recent-change entry.
- Leaving the monitored directory Quick View stops monitoring and prevents its
  pending work from changing a new view or starting a new scan after monitoring
  has been disabled or the controller has been disposed.
- For text files, separator line shows associated app name; info row shows BOM and EOL.
- `BOM: No` shown when there is no BOM (not "No BOM").
- Errors during size scan shown in dark-yellow below the error count.
- No UI freeze while size is being computed.

## Verification

Manual: open a large directory in Quick View and navigate away before scan completes —
the scan must stop; a new one must start for the new directory.

Manual: enable directory monitoring, create, modify, rename, and delete entries
below the selected directory, and confirm recent changes, summary refresh, and
safe cleanup when leaving Quick View. Create more than one history viewport of
changes, then use wheel, Ctrl+Up/Down, Ctrl+PageUp/PageDown, and the scrollbar to
reach older entries without scrolling the underlying file panel. Confirm resize does
not lose retained history or logical selection/viewing position, and that new changes
do not disrupt viewing older entries. Confirm a Changed event within one second of a
Created event appears only as that Created entry. During a burst, including changes
that arrive while a scan is active, confirm the summary
settles to the last filesystem state without overlapping scans. Click the full
monitor row to toggle monitoring without changing the active panel, then click and
keyboard-select visible created, modified, and renamed rows and confirm each opens
its own target in the active ordinary file panel; confirm deleted, missing, and
special-panel cases leave panels unchanged.

Automated: cover the 256-entry logical history bound; Created-to-Changed absorption,
its stable identity and fixed time window; and preserved Changed-to-Changed
coalescing. Cover scroll viewport boundaries, wheel consumption, Ctrl navigation,
resize, and preserving an older-history anchor when new entries arrive. Cover both
interactive initial-scan progress and silent monitor refresh progress, including
publication of the completed refresh result and rejection of a stale cancelled scan.
Cover committed-frame input geometry and assert that the same rendered frame marks
the normalized visible selection. Cover repeated and interleaved modified events,
their stable identity, latest timestamp, repeat indicator, and continued refresh
scheduling; cover that created, deleted, and renamed events remain separate.
Cover concurrent monitor-disable and controller-disposal barriers racing a pending
monitor refresh, proving the refresh cannot start a directory scan or publish UI
state afterward.
