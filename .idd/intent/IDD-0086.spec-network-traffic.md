# IDD-0086.spec-network-traffic

## Intent

Help a user quickly identify applications currently consuming the most network
traffic. This is a first-party native plugin, separate from port diagnostics.

Related: IDD-0061, IDD-0062, IDD-0067.

## Behavior

The Plugins menu exposes `Network Traffic...`; the `traffic` prefix opens the
same live modal screen. Monitoring starts on opening and ends on closing. The
screen refreshes automatically without blocking keyboard, mouse or resize.
Applications sort by recent combined received and sent byte rate, descending.
The main table shows a readable application name, a window title when available,
and current received and sent rates, plus separate downloaded and uploaded byte
volumes accumulated since monitoring started. Prefer the executable's descriptive metadata
for the application name; otherwise use its executable/process name. Use only
standard local process APIs for window captions, without parent-process guesses
or borrowing another application's window. Multiple available titles may belong
to one application row. A missing title never hides the application. Titles
refresh during monitoring and disappear when no longer observed.

The directional cumulative counters are shown directly in the main table as
Downloaded and Uploaded. Enter does not open a details screen. Technical
`Session` and `Estimated` columns are not shown. Help explains that approximate
attribution refers to identifying the owner, not estimating bytes.
Multiple processes with the same known executable path are grouped;
unavailable identities remain distinguishable.

The screen displays unattributed volume and recent rate separately, and makes
approximate ownership and capture loss visible in plain language. Uncertainty must not silently
become an application's measured traffic. Recent rates use event time over a
short rolling window; the screen explains collection warm-up and delivery lag.
An idle application does not remain a top consumer because of past volume.

Windows monitoring uses documented user-mode sources, without a custom driver,
packet payload capture, or security audit policy changes. Administrator access
is required by the current ETW collector. Missing privileges and unsupported
platforms produce actionable explanations, not an apparently successful empty
measurement. No automatic elevation is performed. Demo mode uses deterministic
sample traffic and never starts a real collector.

Collector state is bounded during a long-running screen. Only its own tracing
session is stopped, including after errors and cancellation. Raw experiment
captures and packet data are not written during normal monitoring.

## Architecture and boundaries

The plugin is composed explicitly through the same neutral registration
contract as FTP. It lives in a separate project and uses shared modal and table
controls. Native collection is separated from presentation. External DLL loading
and discovery are outside this change.

## Acceptance criteria

- Menu and command open the same screen; closing releases collection resources.
- A larger recent consumer ranks ahead of a smaller one, including when both
  existed before monitoring started. Rates decay after traffic stops.
- Receive, send, totals, estimates and Unknown stay consistent under refresh;
  ambiguous ownership is never assigned by selecting an arbitrary PID.
- Readable names and available captions help identify applications without
  changing grouping, counters or ordering; names, executable paths, captions
  and process identities can be searched.
- Selection survives name/title updates and reordering. Enter leaves the
  monitoring screen open without a details workflow. Missing metadata and
  window titles remain usable.
- Each row shows separate current receive/send rates and accumulated
  downloaded/uploaded volumes from the start of this monitoring screen.
- Keyboard, mouse, resize, empty/warming-up and error states remain usable.
- Normal-token and unsupported hosts explain availability; demo has no OS effects.

## Verification

Automated checks cover registration, rolling ranking and aggregation, identity
reuse, ambiguity, loss, bounded retention and cancellation. Shared modal tests
protect input and resize. Metadata verification covers title updates, missing
metadata and preservation of application grouping and counters. Windows validation checks live TCP/UDP collection and
owned-session cleanup. Manual review checks live ranking and table usability.
