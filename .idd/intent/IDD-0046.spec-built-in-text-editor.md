## Goal and authority

The built-in F4 editor supports reliable editing and saving, search and replace,
selection, undo/redo, bookmarks, format preservation, and a responsive full-screen
interface. Editor state and operations must remain testable independently of
the console event loop.

This document defines **normative product behavior and durable boundaries**.
It does not prescribe historical stages, specific private classes, buffer
algorithms, compatibility shims or test host implementations. The complete
previous implementation plan and regression inventory are retained as a
[non-normative engineering reference](../../docs/architecture/editor-implementation-reference.md).
Specialized editor requirements are governed by IDD-0049, IDD-0050 and IDD-0051.

## Opening files, formats and saving

- Opening an existing text file detects and records encoding, BOM presence
  and line endings (CRLF, LF, CR or Mixed). Save preserves these properties
  by default, including mixed line endings, until the user explicitly
  selects a different format.
- Reuse the application's shared encoding detection and catalog instead of
  introducing incompatible editor-only detection.
- New documents default to UTF-8 without BOM and the configured default
  editor line ending, not the host process newline convention.
- F2 saves in the selected format. Shift+F2 offers encoding, BOM and
  line-ending changes; selecting a single line-ending mode can normalize
  an originally mixed document.
- Saving marks the current document revision clean only on success. A failed
  save leaves the editor open and retains dirty content and format choices.
  Read-only sessions and file attributes lead to an explicit non-silent
  error or configured read-only editing behavior.
- Editing an item belonging to a writable panel source must read and write
  through that source. Provider-backed edits must not accidentally save to
  an unrelated local path. Local saves must avoid silently losing an
  existing file if a write or replacement fails.
- `Editor.FileSizeLimitBytes` is a warning threshold, not a hard size
  prohibition; `0` disables warning. Exceeding it requires confirmation.
  A file that cannot be decoded or represented safely fails with a clear
  error and leaves the file manager usable.
- Editor find input history persists through the application history
  provider and remains separate from viewer find history.

## Editing and undo/redo

- The editor supports text insertion, deletion, replacement, line splitting,
  line joining and editing around a virtual cursor position without
  rebuilding or serializing the entire file for each ordinary operation.
- `Editor.TabSize` controls tab stops and `Editor.ExpandTabs` controls
  insertion of spaces for new Tab input. Existing tab characters must not
  be silently replaced or rendered as one-cell spaces.
- Text positions and selections are logical. Tab expansion, Unicode/grapheme
  boundaries and terminal-cell widths determine their rendered columns.
  IDD-0051 owns grapheme-safe movement and deletion details.
- Forward Delete at a physical line end joins the next line. At a cursor
  beyond the end in virtual space, it fills the gap with spaces before
  joining; it is a no-op in virtual space on the document's last line.
- Ctrl+Z and Ctrl+Y provide undo/redo. Typed runs are grouped usefully;
  paste, line split/join, replace and block deletion form coherent undo
  transactions. Undo/redo restores text, cursor, selection and dirty/clean
  status; editing after undo clears redo history.
- `Editor.UndoSize` controls history capacity (default `2048`);
  `0` disables undo history. The internal history representation is not
  part of product intent.
- The former 10 MB hard block is not allowed. An automated scenario must
  open, edit, save and reopen a 50 MB UTF-8 text file. Extremely large
  files may fail clearly when actual resource limits are reached rather
  than corrupting text.

## Navigation, search and replacement

- Arrow keys, Home/End, Ctrl+Home/End and PageUp/PageDown follow the
  editor's established navigation semantics. `Editor.AllowEmptySpaceAfterEof`
  configures scrolling below the last line.
- `Editor.WordDiv` determines word boundaries consistently for
  Ctrl+Left/Right, word deletion, whole-word search and double-click
  selection, including newline and empty-line transitions. Word navigation
  must not scan or serialize the entire document on each command.
- Shift navigation reaches the same destination as ordinary navigation
  but extends linear selection from its stable anchor.
- If ordinary linear selection is active, non-Shift relative movement
  collapses it in the requested direction as one movement unit. A single
  Left/Right, Ctrl+Left/Right, Up/Down command does not then move another
  unit; multi-unit vertical motion uses the remaining units. Absolute
  navigation moves directly. Far mark/block modes remain separate.
- F7 opens Find, Shift+F7 repeats search forward, Alt+F7 repeats backward
  and Ctrl+F7 opens Replace. F2 remains Save. These repeat directions
  reflect current editor bindings, not the older staged plan.
- Find and replace support direction, case sensitivity, whole words,
  regular expressions and searching within ordinary linear selection.
  `Editor.F7StartsAtNextCharacter` governs forward-search starting position.
  Invalid regex patterns report validation errors without editing text.
  Replace all is undoable as one transaction.

## Selection, clipboard, bookmarks and status

- Linear and rectangular selections support their relevant copy, cut,
  delete, paste and type-over behavior. Mutations of a selected block
  are undoable. `Editor.BSLikeDel` controls rectangular Backspace.
- Clipboard use follows the application's clipboard abstraction rather
  than requiring a separate editor-specific OS integration.
- Session bookmarks can be set, cleared and navigated and follow lines
  predictably when earlier lines are inserted or deleted. Persistence
  of bookmarks across editor sessions is not required here.
- The header/status indicates path, dirty/read-only state, encoding,
  BOM, line endings, cursor row/column and current character code
  (including decimal and hexadecimal forms).
- Editor function-key actions and their mouse targets follow current
  command bindings, including modifier-sensitive actions.

## Rendering, integration and editor events

- The editor uses shared full-screen composition, modal dialogs, theme,
  scrollbar and accepted-frame input behavior (IDD-0062, IDD-0067).
  Resizing or closing an overlay preserves document state and leaves
  no stale cursor, text, scrollbar or dialog cells.
- Mouse wheel scrolls editor text. Where an editor scrollbar gutter
  is reserved, its width is stable across scrollability changes and
  every full content render clears its owned cells before optionally
  painting a scrollbar. Overlay movement must not leave ghosts there.
- Cursor changes within an unchanged viewport should update cursor/status
  without rebuilding visible content. Modifier-only key-bar changes and
  wide-character caret blink redraw only affected areas without
  bypassing stable-frame commit semantics.
- Visible-line rendering should scale with the visible text range, not
  with complete document size or repeated scans from the start of a
  long line for each terminal cell.
- Internal editor-domain consumers may observe open, input, text change,
  save, close and redraw events, and provide color spans for visible
  ranges. Text mutations must go through normal editor semantics so
  undo and dirty tracking remain correct. IDD-0050 owns non-destructive
  TextMate syntax highlighting.
- The editor core is not tied to C# syntax, a new public plugin model
  or a compatibility layer for external Far editor APIs.

## Non-goals

- Full Far Manager macro/plugin ABI or Lua compatibility.
- LSP, autocomplete, code diagnostics, formatters, linters, a full IDE,
  multi-tab/multi-window editor management, or persistent bookmarks.
- Hex/binary or archive editing; rewriting remote-provider semantics
  beyond preserving supported provider-backed F4 editing.
- Guaranteed arbitrary-size editing beyond available memory without
  a separately justified storage design.
- Mandated private class names, a particular piece-table/rope/buffer
  implementation or migration wrappers for superseded internals.

## Acceptance criteria

1. No fixed 10 MB hard stop; size warnings can be accepted or disabled,
   and resource errors do not break the file manager.
2. Save without format changes preserves encoding, BOM and CRLF/LF/CR/
   mixed endings; new-file defaults and Shift+F2 changes behave as specified.
3. F2 saves, while read-only and failed saves preserve dirty content;
   writable provider-backed files save through their source.
4. Editing, line joining in virtual space, tabs, undo/redo and history
   grouping preserve the intended text, cursor, selection and revision.
5. Word navigation, Shift extension, relative selection collapse, find/
   replace and regex errors respect the described keyboard policies.
6. Linear and rectangular selection, clipboard and bookmarks remain
   coherent through editing and undo.
7. Status, command key bar, Unicode rendering, scrollbar gutter and
   partial redraw stay correct during scrolling, resize and nested modals.
8. Editor events and visible-range coloring do not mutate text outside
   the normal editing transactions.
9. A 50 MB UTF-8 fixture passes open/edit/save/reopen automated testing.

## Verification

- Round-trip representative UTF-8/UTF-16/legacy-encoding and BOM cases,
  mixed/newline preservation and explicit format changes.
- Test read-only, failed, size-warning and provider-backed save paths.
- Exercise undo/redo for typing, paste, line split/join, selection deletion,
  replace-all, bookmarks and redo invalidation.
- Check word separators, navigation/selection collapse, virtual-space Delete,
  regex failures and all find repeat directions.
- Test terminal-cell rendering, scrollbar gutter clearing, partial
  cursor/status/key-bar updates and rejected-frame/resize retries.
- Run the 50 MB scenario and targeted large-file/manual terminal checks.
  The linked engineering reference retains the former detailed test list.
