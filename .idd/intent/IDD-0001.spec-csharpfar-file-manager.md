# IDD-0001 - CSharpFar product vision and system boundaries

## Product purpose

CSharpFar is a keyboard-first, Far-inspired, two-panel console file manager
written in C# for .NET 10. It combines filesystem navigation and operations,
a command line with shell output, history, an internal viewer and an editor.
Mouse interaction complements, but does not replace, core keyboard workflows.

This document owns only the product-wide intent and architecture boundaries.
The [intent index](INDEX.md) routes feature behavior, acceptance criteria and
verification to their owning specifications; it is not a second source of
requirements.

## Product-wide contract

- The ordinary workspace has left and right file panels with independent
  locations, selection, cursor, sorting and scroll state.
- Users can work with files and directories through the panels, operate the
  current shell, and inspect or edit files without leaving the file manager.
  Details of these behaviors belong to their feature specifications.
- Windows, Linux and macOS have separate executable hosts sharing the
  application and domain layers. No host must instantiate another platform's
  services as part of normal startup.
- Platform-specific console access, process execution, file launching,
  credentials, volumes, mount points and terminal modes are selected at
  explicit composition roots rather than by the shared application layer.
- Console rendering and input use the product's shared rendering/UI stack,
  not a third-party full application TUI framework. Unix-like hosts reuse the
  common ANSI/VT layer with platform-specific terminal integration.
- UI orchestration, filesystem access, file operations, settings, shell,
  viewer and editor responsibilities remain separated, not concentrated in
  an executable entry point.
- CSharpFar supports isolated, reproducible demonstration sessions. Runtime
  safety and isolation are owned by `IDD-0087`; deterministic documentation
  recording and visual artifacts are owned by `IDD-0088`.
- The supported platforms retain installable or portable release paths.
  Linux packaging is owned by `IDD-0065`; macOS distribution, bundles and
  updates by `IDD-0076`, `IDD-0077` and `IDD-0082`.

## Specification ownership

Feature-specific constraints, UI behavior, command bindings, persistence,
provider access, packaging, test cases and release workflows are defined
exclusively by their owning documents listed in [INDEX.md](INDEX.md).
In particular, panel-load errors and unregistered-source transitions belong
to `IDD-0030`, not to this overview.

A change to a specific feature updates its owning specification rather than
adding detailed behavior or a parallel acceptance checklist here. Change
`IDD-0001` when the product's purpose, supported platform model or
system-wide boundaries change.

## Non-goals

- Exact Far Manager compatibility, including every hotkey and macros.
- A full IDE-style editor or dedicated hex editor.
- Archive panels as a built-in core feature.
- Complete parity with every platform-specific terminal feature.

## Acceptance criteria

- The product provides a usable keyboard-first two-panel file-manager
  workspace, shell integration, file operations, viewer and editor, with
  details verified by the respective owners in `INDEX.md`.
- Windows, Linux and macOS hosts compose their own platform implementations
  around the shared application rather than requiring unrelated OS services.
- The Windows portable release retains checksum and artifact attestation
  coverage; Linux/macOS packaging is verified by the distribution owners.
- Demonstration sessions and their recording workflows meet `IDD-0087`
  and `IDD-0088` without a parallel verification contract in this document.

## Verification

Use a cross-platform product integration smoke check for host composition
and the core keyboard workflow. Verify Windows portable release provenance
at the product release boundary. Feature-level tests and detailed acceptance
matrices remain with their respective owning specifications in `INDEX.md`.
