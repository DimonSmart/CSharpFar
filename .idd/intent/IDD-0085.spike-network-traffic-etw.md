# IDD-0085 - Network Traffic feasibility spike

Related: IDD-0061, IDD-0062, IDD-0067, IDD-0073.

## Question

Can Windows ETW produce credible per-process received/sent byte counts for
CSharpFar without elevated privileges in the main process, taking over another
ETW session, double accounting or mislabeling local traffic as Internet traffic?

## Constraints

The planned capability is Windows x64 only. The application must stay
unprivileged; any elevated collector is separate and short-lived. The intended
user-facing aggregation is by executable identity, not by display name alone.
Unknown attribution and lost events must remain explicit, and all resource
ownership, child process lifetimes and IPC peers must be authenticated.

## Method

Run the real-time, uniquely named ETW feasibility probe on Windows 10/11.
Examine event payload IDs, size semantics, four directional protocol families,
IPv4/IPv6, event buffering, lost events, process epochs and ETW privileges.
Repeat under elevated/non-elevated accounts and document results in
docs/research/network-traffic-etw-spike.md. No dummy port-count estimate
can substitute for traffic bytes.

## Result

Not determined. Initial probe and reproducible CI diagnostic have been added;
Windows measurements and a Go decision are still missing.

## Recommendation

Do not register a Network Traffic native plugin or claim working network
measurement until an evidence-backed Go decision is recorded. Once the gate
passes, capture durable behavior in a new owning specification, connect it
to IDD-0061/0062/0067, and remove this resolved spike from the intent index.
