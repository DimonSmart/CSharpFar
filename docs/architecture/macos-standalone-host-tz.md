# ТЗ: самостоятельное macOS-приложение CSharpFar

## 1. Цель

Превратить `CSharpFar.app` из запускающего скрипта для внешнего терминала в
самостоятельное macOS-приложение с собственным окном, именем, иконкой и
жизненным циклом. Сохранить существующий терминальный интерфейс и общее ядро
файлового менеджера.

Продуктовый контракт: [IDD-0077](../../.idd/intent/IDD-0077.spec-macos-application-bundle.md).
Этот документ описывает техническое задание для реализации. Принятое
архитектурное решение о SwiftTerm v1.14.0 зафиксировано в
[IDD-0084](../../.idd/intent/IDD-0084.adr-macos-terminal-engine.md).
Ручная приёмка под macOS необходима независимо от результатов CI.

## 2. Исходная проблема

Сейчас `Contents/MacOS/CSharpFar` запускает bundled CLI в установленном kitty
или Terminal.app. Графическое окно создаёт терминал, поэтому macOS показывает
его идентичность в Dock и Cmd+Tab. Иконка `CSharpFar.app` в Finder этого не
меняет.

Основные места текущей реализации:

- `src/CSharpFar.Host.MacOs/MacOsTerminalLauncher.cs` — внешний терминал;
- `eng/packaging/build-macos-app.ps1` — сборка bundle и launcher;
- `src/CSharpFar.App/Updates/MacOsHomebrewUpdateInstaller.cs` — обновление;
- настройка `application.preferredMacOsTerminal` — выбор терминала.

## 3. Целевая архитектура

В `CSharpFar.app` находится desktop-хост, который владеет macOS-окном и
встроенной терминальной поверхностью. Хост запускает общий `csharpfar` в
псевдотерминале (PTY). Файловый менеджер и выполняемые им интерактивные команды
работают на slave-стороне PTY; встроенный терминал обрабатывает поток со стороны
master и отображает его в окне.

Распределение ответственности:

- Desktop-хост: окно, системное меню, активация, terminal engine, PTY,
  клавиатура/мышь/clipboard, размеры, управление сеансом и ошибки запуска.
- Общий `csharpfar`: панели, редактор, просмотрщик, команды, настройки,
  файловые операции и существующий ANSI/VT-протокол.
- Терминальный движок: интерпретация VT, экранные буферы, сетка символов,
  scrollback и преобразование событий в согласованный терминальный протокол.

Не переписывать файловый менеджер на нативные виджеты. Не встраивать отдельную
реализацию панелей в desktop-хост. Не изменять установленный пользователем
kitty и не маскировать его переименованием bundle или подменой иконки.

## 4. Обязательное поведение

### Идентичность и запуск

- Имя приложения — `CSharpFar`, bundle identifier — `com.dimonsmart.csharpfar`.
- В Finder, Dock, Cmd+Tab и системном меню используется идентичность CSharpFar.
- Запуск из Finder, Dock, Spotlight и Launchpad открывает собственное окно.
- Закреплённая иконка запускает приложение; активация возвращает его окно.
- Повторное обычное открытие активирует существующее окно. Явный запуск
  отдельного экземпляра поддерживается для перезапуска после обновления.
- Стартовый каталог desktop-сеанса — домашний каталог пользователя.
- Установка kitty, .NET runtime или другого терминала не требуется.
- Первый запуск не скачивает дополнительные компоненты.

### Совместимость терминала

Сохранить панели, меню, диалоги, редактор, просмотрщик, цвета и горячие клавиши.
Обеспечить main/alternate screen, cursor, scrollback, Unicode, изменение
размеров и корректную работу на Retina и обычных дисплеях.

Поддержать клавиатурный контракт IDD-0064: согласование enhanced keyboard
protocol, профиль 27, нажатие/повтор/отпускание, самостоятельные Shift/Alt/Ctrl
и сброс удерживаемых модификаторов при потере фокуса. Название Kitty keyboard
protocol не означает зависимость от приложения kitty. Нельзя объявлять
поддержку протокола без реализации его согласованного поведения.

Проверить ввод кириллицы, составных символов, символов вне BMP и IME без
дублирования. Сохранить клики, двойные клики, wheel, drag и passive motion.
В скрытом режиме Ctrl+O должна работать терминальная селекция текста.
Cmd+C копирует выделение, Cmd+V вставляет текст один раз. Ctrl+C сохраняет
терминальное значение; Cmd+C без выделения не превращается в Ctrl+C.

### Команды и управление процессами

- CLI-процесс получает настоящий controlling TTY и корректную process group.
- Интерактивные команды выполняются в том же окне и могут читать stdin.
- Ctrl+C прерывает foreground-команду, сохраняя CSharpFar.
- После завершения команды восстанавливаются панели, режим ввода и мышь.
- Resize обновляет размер PTY и доставляется приложению/foreground-команде.
- Потоковый вывод не теряется и не блокирует обработку системных событий окна.
- Открытие документов через macOS-ассоциации сохраняется.

### Завершение и ошибки

- Выход из CSharpFar закрывает сеанс и освобождает PTY и процессы.
- Закрытие окна и Cmd+Q проходят через штатную проверку несохранённых данных
  и активных операций. Отмена закрытия оставляет приложение работоспособным.
- При работающей foreground-команде требуется выбор: завершить сеанс или
  отменить закрытие. После подтверждения не остаётся принадлежащих сеансу
  процессов; отдельно запущенные приложения по ассоциациям не закрываются.
- Ошибка запуска показывается пользователю с возможностью закрыть окно.
- Неожиданное завершение ядра отличается от штатного выхода и отображается
  пользователю. Авария хоста освобождает терминальный сеанс.
- Нет скрытого fallback в kitty/Terminal.app или дублирующих сеансов.
- Диагностика следует IDD-0081; ввод и полное содержимое терминала по умолчанию
  не записываются.

## 5. Совместимость и поставка

- Сохранить portable CLI и Homebrew Formula, поведение Windows и Linux.
- Сохранить прямой запуск bundled `Contents/Resources/csharpfar` в TTY,
  аргументы CLI, `--version`, `--check-system-git`, `--check-terminal` и Input Lab.
- `--version` и `--check-system-git` через bundle executable не открывают окно.
- Сохранить самодостаточные arm64/x64 app ZIP, release version, checksums и
  attestations. CLI внутри bundle совпадает с соответствующим portable binary.
- Все зависимости хоста входят в bundle и соответствуют его архитектуре.
- Сохранить установку Cask и About → Update now по IDD-0082. После обновления
  запускается новый desktop-хост. Успех `open -n` означает принятие запроса,
  а не подтверждённую готовность интерфейса.
- Старые `preferredMacOsTerminal` допустимы при чтении настроек, но не влияют
  на desktop-запуск. Убрать неработающий выбор провайдера из UI; остальные
  настройки и пользовательские данные сохранить.
- Подпись и notarization не входят в эту задачу; сохранить действующие
  ограничения и инструкции установки неподписанного приложения.

## 6. Порядок реализации

1. **Проверка движка.** Сравнить подходящие встраиваемые terminal engines по
   macOS embedding, arm64/x64, VT/PTY, keyboard profile 27, IME, лицензии,
   сопровождению и возможности включить зависимости в bundle. Проверить
   совместимость минимальной версии macOS с текущей поставкой. Выбор и
   необходимые дополнения оформить отдельным ADR после исследования.
2. **Рабочий прототип.** Получить собственное окно CSharpFar с реальным PTY,
   работающими панелями, resize и интерактивной дочерней командой. Доказать
   Dock/Cmd+Tab identity и полный клавиатурный контракт до основной интеграции.
3. **Интеграция.** Довести ввод, clipboard, экраны, scrollback, управление
   процессами, закрытие/отмену и ошибки. Удалить внешний терминал из desktop-пути.
4. **Поставка.** Обновить bundle packaging, release-проверки, Cask caveats,
   README, устаревшую матрицу terminal preference и проверки обновления.
5. **Приёмка.** Пройти сценарии ниже на Apple Silicon и Intel. Отсутствие
   проверки одной архитектуры явно фиксируется как незакрытая приёмка.

Не выбирать библиотеку только по наличию красивого терминального виджета:
прототип должен подтвердить ввод, процессы и системную идентичность. При
недостатке протокольной поддержки оценить доработку или другой движок до
продолжения основной реализации.

## 7. Критерии приёмки

| Сценарий | Ожидаемый результат |
| --- | --- |
| На Mac нет kitty | CSharpFar запускается в собственном окне |
| Kitty уже работает | Его окно, иконка и настройки остаются независимыми |
| Finder / Dock / Spotlight / Launchpad | Запуск приложения с идентичностью CSharpFar |
| Cmd+Tab, Dock activation, закрепление и повторный запуск | Возврат к нужному окну без внешнего терминала |
| Обычное повторное открытие / явный новый экземпляр | Активация текущего / отдельный рабочий сеанс |
| Панели, редактор, просмотрщик, диалоги | Сохраняются существующие функции |
| Modifier lifecycle и потеря фокуса | Нет потерянных клавиш и застрявшего Shift/Alt/Ctrl |
| Кириллица, Unicode, IME, clipboard | Текст передаётся без порчи и дублирования |
| Mouse, drag, wheel, Ctrl+O selection | Работают режимы приложения и терминала |
| Resize, fullscreen, смена display scale | Корректные размеры PTY и читаемый интерфейс |
| Интерактивная/fullscreen-команда и большой вывод | Один терминал, доступный ввод, упорядоченный вывод |
| Ctrl+C в foreground-команде | Команда прервана, CSharpFar продолжает работу |
| Несохранённый редактор / активная операция / child при Cmd+Q | Штатное решение о завершении, рабочая отмена |
| Подтверждённое закрытие и аварийные сценарии | Нет зависших процессов сеанса; ошибка видна |
| Legacy provider settings | Запуск собственного хоста, данные сохранены |
| CLI и диагностика | Прежнее поведение, без неожиданного окна |
| Cask install и About update/relaunch | Установлена нужная версия, открыт новый desktop-хост |

Автоматизировать минимальный набор значимых проверок: bundle metadata,
архитектуры и зависимости, CLI parity, аргументы, PTY resize, interruption и
жизненный цикл. Dock, Cmd+Tab, IME, реальные модификаторы и display scaling
проверить на macOS вручную. Не добавлять тесты тривиальных деталей реализации.

## 8. Результат работы

Рабочий desktop-хост; обоснованный ADR выбора движка; app artifacts для обеих
архитектур; совместимый CLI; обновлённая пользовательская документация;
автоматические проверки ключевых контрактов и результаты ручной приёмки.
Задача завершена после выполнения критериев приёмки, включая установку и
перезапуск после обновления.
